# Requirements: Barahlo — учёт корпоративной техники

**Defined:** 2026-09-28
**Milestone:** v1.2 Гигиена данных
**Core Value:** Мгновенный точный ответ: где находится конкретная единица техники, кто ею пользуется и какая у неё конфигурация — за секунды, поиском или фильтром.

## v1.2 Requirements

Требования вехи v1.2. Каждый маппится ровно на одну фазу роадмапа.

### Правка истории (HIST)

- [x] **HIST-01**: Оператор может исправить запись в истории устройства — сотрудника, дату, тип действия и комментарий
- [x] **HIST-02**: Оператор может удалить ошибочную запись из истории устройства с подтверждением
- [x] **HIST-03**: После правки или удаления записи таймлайн и текущий статус устройства (держатель, статус) отражают изменения сразу

### Удаление устройств (DEL)

- [x] **DEL-01**: Оператор может удалить устройство целиком одним действием с явным подтверждением
- [x] **DEL-02**: Удалённое устройство исчезает из реестра, поиска, ⌘K, дашборда и CSV-экспорта; его история удаляется вместе с ним

## Future Requirements

Хвост v2-бэклога (не в текущем роадмапе):

- **FLT-01**: Сохранённые фильтры реестра («мои фильтры»)
- **QR-01**: QR-этикетки на устройства: печать стикера со ссылкой на карточку
- **ACT-01**: Акт приёма-передачи: печатная форма по выдаче

## Out of Scope

| Feature | Reason |
|---------|--------|
| Правка полей устройства | Уже есть с v1.0 (updateDeviceAction) — не дублируем |
| Массовое удаление устройств | Нет сценария: ошибки ввода единичны |
| Корзина / восстановление удалённого | Жёсткое удаление выбрано владельцем (4г: минимум механики); бэкапы БД — страховка |
| Корректирующие записи в таймлайне вместо прямой правки | Владелец выбрал прямую правку (аудиторский след «было так» не нужен для одного оператора) |
| Сохранённые фильтры, QR-этикетки, акт приёма-передачи | Отложены владельцем (4г) в Future Requirements |
