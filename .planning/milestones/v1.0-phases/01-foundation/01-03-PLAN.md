`scripts/backup.mjs` — Pattern 5 из PATTERNS.md дословно, с двумя уточнениями. Скрипт читает `DATA_DIR` (по умолчанию './data'), каталог бэкапов `join(DATA_DIR, 'backups')`, папка дня — `YYYY-MM-DD` ЛОКАЛЬНОЙ даты сервера (не UTC ISO: `new Date()` и ручное форматирование local-year-month-day, чтобы имя папки совпадало с датой на сервере; конвенция «локальная дата» фиксируется и в README — Pitfall 9). Порядок работы: (1) если папка дня существует → «уже есть» и exit 0 (идемпотентность перезапуска cron); (2) открыть живую БД `join(DATA_DIR, 'app.db')` и `await db.backup(join(dest, 'app.db'))` — online backup API, консистентный под WAL, без остановки записи; (3) открыть КОПИЮ readonly и `pragma('integrity_check', { simple: true })`; результат не 'ok' → stderr + exit 1 (D-14); (4) скопировать `uploads/` рекурсивно, если каталог существует (в фазе 1 его может не быть — тогда создать пустой в копии, чтобы структура восстанавливалась единообразно); (5) ротация: отсортированные имена папок, всё старше 30 самых свежих удалить рекурсивно (D-06); (6) stdout-строка «backup ok: <путь>». Файл `.mjs`, только better-sqlite3 + node:fs/node:path, никаких секретов в выводе. Живую БД открывать с busy_timeout=5000 (ночная запись маловероятна, но прагма дешёвая).

`tests/backup.test.ts` — behavior ниже; тесты создают temp-каталог данных, БД с таблицей и строками, вызывают логику скрипта.
