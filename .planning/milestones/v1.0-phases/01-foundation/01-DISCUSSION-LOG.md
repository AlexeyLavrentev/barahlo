## Раунд 1

### Q1 — Инвентарные номера: источник и генерация

| Option | Description | Selected |
|--------|-------------|----------|
| Автогенерация `ГГГГ-NNNN` | Приложение генерит следующий по маске | |
| Продолжить корпоративную нумерацию | Формат от пользователя | |
| Ручной ввод | Номера присваивают бухгалтерия/ИТ, вписываешь как есть | ✓ |

**User's choice:** Ручной ввод — номера выдаёт 1С (базы бухгалтерии и ИТ-отдела), формат вида `ИБ-0000146`

## Раунд 2

### Q6 — Уникальность инвентарника

| Option | Description | Selected |
|--------|-------------|----------|
| UNIQUE-констрейнт | Дубль = опечатка, ввод блокируется | ✓ (из ответа) |
| Обычный индекс без UNIQUE | Дубли живут, разруливаются вне приложения | |

**User's choice:** Дублей в 1С «обычно не бывает» → UNIQUE безопасен и ловит опечатки. Записано как UNIQUE на нормализованный инвентарник.

### Q7 — Публичный GitHub и .planning/

| Option | Description | Selected |
|--------|-------------|----------|
| GitHub публичный, .planning/ в gitignore | Код открыт, кухня локальна | |
| Всё публично | Кухня наружу | |
| Канон — корпоративный GitLab, GitHub — чистое зеркало кода | Work-доки на GitHub не текут | ✓ |

**User's choice:** На GitHub ничего с работы; канонический приватный репо — корпоративный GitLab (код + .planning/, git pull деплоя оттуда). Публичный GitHub — только вычищенный код, позже.
