## Spacing Scale

Inherited from 02-UI-SPEC unchanged: xs 4 / sm 8 / md 16 / lg 24 / xl 32 / 2xl 48 / 3xl 64. Standing exceptions hold (44px min interactive height `min-h-11`; 48px header `h-12`; 12px control padding-x `px-3`; `mt-1.5`/`py-2.5`/`px-2.5` forbidden; half-step `mt-3`/`gap-3` = 12px allowed as in phase 3 card groups).

Phase 4 specifics:
- **Actions row on device card:** existing `mt-6 flex gap-2`, gains `flex-wrap` — up to 5 buttons (assigned status) wrap to a second line on narrow screens; wrapping is correct behavior, not a bug.
- **Timeline rows:** `pl-6` (24px) text indent from the dot column; `pb-4` between events; dot `size-2` at `left-0`; 1px connector `w-px bg-hairline` centered under the dot (the ~3.5px x-offset is dot-alignment math, not spacing rhythm). 8px dot is a half-step of the 4px grid.
- **Photo grid:** `grid grid-cols-3 sm:grid-cols-4 gap-2`; tiles `aspect-square`; add-tile same footprint.
- **List thumbnail:** `size-10` (40px, on-scale), row keeps `min-h-11 px-4 py-2` with `gap-3` to the text block.
- **Action dialogs:** same `max-w-md p-6` recipe as phases 2–3; body scrolls `max-h-[85svh] overflow-y-auto` only if content exceeds viewport (dispose dialog with warning + 2 fields stays under it in practice); footer pinned.
- **Photo lightbox:** panel `max-w-3xl p-4`; image `max-h-[70svh] w-auto rounded-lg`.

## Typography

Inherited unchanged — exactly 4 sizes, exactly 2 weights (400 + 600; no 500 anywhere):

| Role | Size | Weight | Line Height | Tracking | Tailwind |
|------|------|--------|-------------|----------|----------|
| Label / secondary | 14px | 400 | 1.45 | 0 | `text-sm` |
| Body | 16px | 400 | 1.5 | 0 | `text-base` |
| Heading | 20px | 600 | 1.2 | -0.01em | `text-xl tracking-tight` |
| Display | 28px | 600 | 1.2 | -0.02em | `text-[28px] tracking-[-0.02em]` |

Role assignments for this phase:
- **Display (28/600):** unchanged — device card title (model), employee card title.
- **Heading (20/600):** card section headers «История перемещений», «Фото», «Техника»; dialog titles («Выдать устройство», «Списать устройство», «Вернуть всю технику?»…).
- **Body (16/400):** all input/select/textarea text in action dialogs (16px prevents iOS zoom), issued-device model name on the employee card, photo-lightbox-less body copy where a sentence stands alone.
- **Label (14/400):** timeline route/meta lines and dates, timeline comments (user content, compact context), photo counter «3 из 8», form labels, hints, placeholders, secondary buttons, validation errors, dialog warning/body copy.
- **14/600 (the allowed third weight application, phase 3 «in-dialog group header» recipe):** timeline event labels («Выдача», «Возврат»…) — `text-sm font-semibold text-ink`. A timeline is a list of mini-headers, not prose.
- **Controls:** dialog primary 14/600; secondary buttons 14/400 (unchanged). Mono (`font-mono text-sm`) on serial numbers wherever they appear in phase 4 UI (issued-device rows line 2, timeline route lines).

| Secondary (30%) | `#FFFFFF` (`bg-surface`) | List cards, card sections, dialogs, header bar, combobox/select popovers, lightbox panel |
| Text primary | `#1D1D1F` (`text-ink`) | Titles, values, event labels, comments |

| Accent (10%) | `#0071E3` (`bg-accent`) | Reserved list below — nowhere else |
| Destructive | `#D70015` | **Finally used, exactly where reserved:** (a) solid fill of the «Списать» confirm button (white 14/600 text, hover `bg-destructive/90`); (b) inline validation text (standing error semantics); (c) tinted «Списано» status pill (`bg-destructive/10 text-destructive`) — terminal state marker, same semantic family as the button |

Accent reserved for exactly three things (phase 4 extension of the phase 2/3 list):
1. **Dialog primaries of the five reversible custody actions** — «Выдать», «Принять», «Передать», «В ремонт», «Из ремонта» (solid `#0071E3`, white 14/600, hover `#0077ED`, `active:scale-[0.97]`). **On the device card itself: at most ONE accent button — the forward action of the status** («Выдать» when in_stock, «Из ремонта» when repair); an assigned device gets no accent (Принять/Передать/В ремонт are equally likely, all secondary).
2. Focus state: input/select/textarea focus ring `ring-2 ring-accent/30` + focused border `#0071E3` (unchanged).
3. Select/combobox affordances: checkmark and selected-row highlight in the employee picker (unchanged).

Explicitly NOT accent and NOT red: timeline dots, photo add-tile, «Вернуть всю технику» (confirm primary = neutral solid `bg-ink text-white`, archive-confirm precedent — the operation is safe, devices stay in stock), photo deletion (neutral; **red is contractually reserved for «Списать» as the only destructive action**, E-03), status pills «На складе»/«Используется»/«В ремонте» (neutral `bg-black/5` — color arrives only for the terminal «Списано», see Defaults).

All: centered `max-w-md p-6`, field recipe as phases 2–3 (Label + control `h-10 px-3 text-base`, inline error 14/400 `#D70015` under the field, `aria-invalid`), footer = dismiss (secondary) + primary (right). Field order everywhere: **сотрудник → дата события → комментарий** (declared discretion). «Дата события» = `input type="date"` **prefilled with today** (E-01 default «сейчас»; user edits to backdate), validated not-in-future. «Комментарий» = text input, `maxLength` 500, optional, placeholder «Номер акта, примечание…». Pending copy per table below; failures render the action error with `role=alert`, values echoed (React-19 form-reset pattern, known-issue fix from 03-UAT).

Employee picker: the existing combobox re-parametrized — options = active employees (`isActive = 1`, sorted А→Я `Intl.Collator('ru')`), selected row accent checkmark, **no create-option** (departments had «Создать „X“»; employees are never created from a custody dialog). Zero active employees → the empty-state hint inside the popover: «Нет активных сотрудников — добавьте их в разделе „Сотрудники“.»

### Timeline («История перемещений» group — replaces placeholder; MOVE-04)

Vertical timeline (declared discretion: лента chosen over plain list — visual history reads topologically). Newest first. Per item: 8px dot (`size-2 rounded-full bg-hairline`; **newest item's dot `bg-ink-secondary`** — quiet emphasis of current state), 1px `bg-hairline` connector to the next (older) item, none after the last. Content: event label (14/600 ink) · meta line (14/400 secondary): «{dd.mm.yyyy, hh:mm} · {маршрут}» · comment (14/400 ink, wraps) when present. Route line per event type (names are plain text, not links — accent/link discipline; archived employees appear as text exactly like active ones, history is history):

| eventType | Label | Route line |
|-----------|-------|------------|
| `received` | Поступление | — |
| `assigned` | Выдача | → {кому} |
| `transferred` | Передача | {от кого} → {кому} |
| `returned` | Возврат | ← {от кого} |
| `to_repair` | В ремонт | от {держателя, если был} |
| `from_repair` | Из ремонта | — |
| `disposed` | Списание | — |

Missing name slots render «—» per the standing dash rule. A missing comment renders nothing (no empty row). Events are never editable or deletable in the UI — no affordance exists (MOVE-04; DB append-only triggers back this).

### Photos

Accessibility fallbacks: lightbox close `aria-label="Закрыть"`; thumbnail buttons alt/aria-label «Фото {n} из {всего}». («Фото» group — replaces placeholder; REG-05, E-05, E-06)

Section header row: «Фото» (20/600) + counter right (14, secondary): «{n} из 8». Grid below (`mt-3`, `grid-cols-3 sm:grid-cols-4 gap-2`):
- **Thumbnail tiles:** `aspect-square rounded-lg object-cover`, each a button opening the lightbox.
- **Add tile** (hidden at 8/8): same footprint, `border border-dashed border-hairline rounded-lg`, centered `plus` icon 20px secondary + «Добавить» (14, secondary). Wraps a hidden `input type="file" accept="image/*" multiple` — on phones the OS sheet offers «Сделать фото» (E-06); the `capture` attribute is NOT set (it would force the camera and block library choice). Upload pending: tile shows «Загрузка…» fill `bg-black/5`, input disabled.
- **Lightbox:** standard dialog recipe, panel `max-w-3xl p-4`, image `max-h-[70svh] w-auto rounded-lg`; footer: «Удалить фото» (secondary, left) — opens confirm dialog: title «Удалить фото?», body «Фото будет удалено безвозвратно.», buttons «Удалить» (neutral solid `bg-ink`) / «Не удалять». Close = scrim / `x` button. Deletion removes the attachment row + disk file; **it is not a history event and writes nothing to the timeline** (E-05).
- Pipeline contract (planner/executor): client resize to ~1600px long edge → server sharp re-encode (JPEG/WebP) with EXIF stripped (orientation applied at re-encode) → `data/uploads/<deviceId>/` + `attachments` metadata; thumbnails = sized `<img>` variants of the same authorized route (`/api/devices/{id}/photos/{attachmentId}?variant=thumb` naming at planner's discretion). Photos of a `disposed` device render read-only: add tile and «Удалить фото» hidden (E-03 view-only).

### Employee card — «Техника» (EMP-02, E-07)

Header row: «Техника» (20/600, exists) + count right (14, secondary, `pluralDevices`). White list card (`mt-3`, `divide-y divide-hairline`): one row per currently issued device (status `assigned`, `currentEmployeeId = this employee`), whole row a link to `/devices/{id}`, `min-h-11 px-4 py-2`, chevron 16px. **Line 1:** модель (16/400 ink, truncate). **Line 2 (14/400 secondary):** {серийник `font-mono`} · «выдано {dd.mm.yyyy}» (date of the latest `assigned` event). Empty state keeps the phase 2 copy «Пока ничего не выдано». Beneath the list (`mt-3`), only when count ≥ 1: secondary button «Вернуть всю технику» → the confirm dialog above. Row thumbnails NOT added here (list-thumbnail rule is the devices list; see Defaults).

### Devices list (only change: thumbnails)

Rows keep the exact phase 3 recipe (two lines, status pill, chevron). One addition: when the device has ≥ 1 photo, a leading thumbnail `size-10 rounded-lg object-cover shrink-0` before the text block (`gap-3`); devices without photos render no placeholder box — text position varies by row, Apple-Files-style (Defaults #9).
