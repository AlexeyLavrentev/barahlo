**User story.** **Как** руководитель, **я хочу** восстановить доступ одной командой на сервере, если забыл пароль, и наполнить локальную базу правдоподобными данными для разработки, **чтобы** фазы 2–6 строились на живых данных, а не на пустых экранах (ACC-01, ACC-03; D-02, D-11).

Output: scripts/reset-admin.mjs, scripts/seed.mjs, lib/normalize.mjs + типизированный ре-экспорт, tests/normalize.test.ts.
</objective>

Поля по типу заполняются по схеме: ram_gb 8/16/32, ram_upgraded 0/1 (~30% ноутбуков), ssd_gb 256/512/1024, screen_diagonal 24/27/32, panel_type 'IPS', port_count 6–12, peripheral_kind из списка. Серийники — уникальные латинские строки вида 'SN-XXXXNN' (после normalizeSerial — по-прежнему уникальные); инвентарники — формат 1С «ИБ-0000NNN» без ведущих нулей-дублей, часть (~20%) devices — с NULL инвентарником (D-16: номер присваивают 1С/ИТ, не у всего есть); serial_normalized/inventory_normalized всегда через импорт из lib/normalize.mjs. purchase_date случайные 2023–2026, supplier из списка, purchase_price правдоподобные рубли, warranty_until = purchase_date + 1/2/3 года, notes у части.

Произвести всё через prepared statements; прагмы и RESTRICT-FK сохраняются.

Финал: печатает сводку — количество отделов/сотрудников/устройств по типам/движений по типам событий.
