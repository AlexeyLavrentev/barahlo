### 1. Открытие / ESC / скролл-лок (SC 1)
- **Проверка:** клик по фото открывает лайтбокс крупно (панель ~max-w-5xl); ESC закрывает;
  страница под диалогом не прокручивается, после закрытия скролл работает.
- **Результат:** pass
- **Доказательство (automated):** панель 994px, классы `max-w-5xl sm:max-w-5xl` в DialogContent;
  `body.overflow=hidden` при открытии → `(none)` после закрытия; скролл восстановлен
  (scrollTo 200/0); ESC закрывает диалог; probe `[data-slot="dialog-content"][data-open]` жив.

### 2. Wheel-зум к курсору (SC 2)
- **Проверка:** колесо зумит к позиции курсора в диапазоне [1,4]; страница под диалогом
  НЕ скроллит во время зума; колесо над контролами инертно; в консоли нет Intervention.
- **Результат:** pass
- **Доказательство (automated):** wheel −240 → scale 1.4333 (=e^0.36, формула колеса);
  zoom-to-point ошибка ≤0.7px (субпиксель замера bounding-box); агрессивное колесо клэмпится
  ровно на 4.0; wheel над close-кнопкой инертен (scale/tx/ty неизменны); scrollY до/после
  wheel идентичен; консоль сессии: 0 warnings/Intervention.

### 3. Жесты: drag / pinch / даблтап (SC 2)
- **Проверка:** drag панорамирует при зуме; pinch зумит к midpoint в [1,4]; двойной
  клик/тап тогглит 1↔2.5 к точке; одиночный инертен; сброс пальца 2→1 без рывка.
- **Результат:** pass (десктоп + CDP touch); живой iPhone — за оператором (см. Current Test)
- **Доказательство (automated):** даблклик 1→2.5 к точке (error=0.00px); drag-pan работает,
  масштаб стабилен 2.5; пан клэмпится ровно на границе |t|=(scaled−stage)/2 (tx=−537.75
  при overflow 1075.5); одиночный клик инертен; CDP-touch pinch: разведение 2 пальцев
  1→1.88→4.0 (клэмп точен), сведение 4→1.0 (пол точен); подъём пальца 2→1 — scale
  стабилен, пан с оставшимся пальцем гладкий (реанкер без рывка).

### 4. Сбросы: смена фото и pointercancel (SC 3)
- **Проверка:** переход prev/next сбрасывает зум на (1x, 0, 0); агрессивный обрыв жеста
  (pointercancel) не залипает — включая реальный iPhone.
- **Результат:** pass (десктоп + синтетика); живой iPhone — за оператором (см. Current Test)
- **Доказательство (automated):** зум 2.5 → next → матрица ровно (1, 0, 0); синтетический
  pointercancel посреди drag — гвард сбросил всё: следующий одиночный клик инертен
  (downRef очищен), повторный drag реанкерится гладко (сдвиг ≤30px без скачка), даблтап
  после cancel жив (2.5→1 тогл).

### 5. Навигация: стрелки, клавиши, края, M=1 (D-01)
- **Проверка:** стрелки листают; ←/→ работают; крайние стрелки disabled (не скрыты);
  при M=1 стрелок нет, счётчик «1 из 1» остаётся; счётчик обновляется.
- **Результат:** pass
- **Доказательство (automated):** счётчик «1 из 4»→«2 из 4»→«1 из 4», клэмп на «4 из 4»;
  prev disabled+visible на первом, next disabled+visible на последнем, prev enabled на
  последнем; ←/→ листают и клэмпятся на краях; при M=1 обе стрелки ОТСУТСТВУЮТ,
  счётчик «1 из 1».

### 6. Контракты: ⌘K / «Удалить фото» / disposed (SC 4, D-06)
- **Проверка:** ⌘K-поверхность жива при открытом лайтбоксе (проба
  `data-slot="dialog-content"` распознаёт лайтбокс — контракт инерции фазы 11: палитра
  не открывается поверх чужого диалога, «command-palette.tsx нулевые правки»);
  «Удалить фото» доступна при любом зуме, delete-флоу работает; disposed — view-only.
- **Результат:** pass
- **Примечание (уточнение формулировки):** ROADMAP SC 4 «⌘K-палитра открывается при
  открытом лайтбоксе» трактован планом 15-02 и UI-SPEC (approved) как «проба жива»:
  обёртка dialog.tsx не менялась, палитре нулевые правки → поведение идентично v1.1
  (probe «another dialog owns the surface», коммит 9e51571). Проверено ОБЕ стороны:
  при открытом лайтбоксе Ctrl/Meta+K инертен (probe hit, палитра не открывается),
  без лайтбокса палитра открывается. Открывание поверх лайтбокса потребовало бы правок
  палитры — против «нулевых правок» и против смысла ROADMAP-обоснования.
- **Доказательство (automated):** probeHit=true при открытом лайтбоксе; палитра открывается
  без лайтбокса; удаление при зуме 2.5: confirm «Удалить фото?» с нейтральным ink-primary
  (НЕ красный — контракт), фото удалено, «4 из 8»→«3 из 8», лайтбокс закрылся чисто;
  disposed-устройство: add-tile исчез, лайтбокс открывается, «Удалить фото» отсутствует,
  зум работает (2.5).

### 7. Fade-in загрузки full-варианта (SC 4)

- **Проверка:** (а) сломанное фото — alt ВИДЕН на приглушённом стейдже, раскладка не
