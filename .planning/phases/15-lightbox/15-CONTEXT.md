# Phase 15: Лайтбокс фото устройства - Context

**Gathered:** 2026-10-01
**Status:** Ready for planning

<domain>
## Phase Boundary

PHOTO-01: усиление существующего лайтбокса карточки устройства (Base UI Dialog в `photo-grid.tsx`) до полноценного просмотра фото — крупная панель (~max-w-5xl, зум-стейдж внутри DialogContent), зум способами из требования (колесо мыши к позиции курсора, двойной клик, pinch на тачскрине), drag-панорамирование, предсказуемый сброс, масштаб ограничен [1,4]. Контракт лайтбокса не меняется: удаление фото остаётся доступным из лайтбокса, ⌘K-палитра открывается при открытом лайтбоксе (проба `data-slot="dialog-content"` жива), ESC закрывает, скролл-лок корректно снимается. Усиление, не замена: без сторонних лайтбокс/зум-библиотек, без изменений photo-пайплайна (фаза — клиентский остров без write-path риска).

</domain>

<decisions>
## Implementation Decisions

### Навигация между фото
- **D-01:** prev/next-навигация внутри лайтбокса: стрелки по краям зум-стейджа + клавиши ←/→; переход сбрасывает зум и пан на (1x, 0, 0); не циклическая — на первом/последнем фото соответствующая стрелка инертна. Основание: SC 3 «переключение на другое фото сбрасывает зум» осмысленно только при переключении внутри лайтбокса — модальный диалог блокирует грид тумбнейлов, «закрыть и открыть другое» вырождает SC 3 в тривиальность; `lightboxIndex` уже существует, delete-кнопку решение не затрагивает. — **Reversibility:** reversible — локальный стейт индекса и пара кнопок в одном клиентском острове.

### Зум-жесты (тонкая настройка сверх SC 2)
- **D-02:** Одиночный клик инертен — зум-тоггл только двойным кликом (SC 2 «клик (двойной)»), иначе одиночный клик конфликтует с распознаванием drag-pan. Двойной клик зумит к позиции курсора (паритет с колесом из SC 2) и возвращает к 1x при повторном. Сброс зума: двойной клик при зуме, переход prev/next (D-01), закрытие диалога. — **Reversibility:** reversible.

### Композиция стейджа
- **D-03:** DialogContent расширяется до ~max-w-5xl (SC 1); внутри — зум-стейдж (overflow-hidden) с изображением на CSS-transform (translate + scale). «Удалить фото» и close-кнопка рендерятся поверх стейджа, вне трансформации, и всегда смонтированы при canMutate (SC 4 «кнопка остаётся смонтированной над трансформированным изображением»); drag-pan не начинается на контролах. Загрузка full-варианта — без пустого мигания (SC 4): изображение проявляется fade-in по onLoad на приглушённом фоне стейджа. — **Reversibility:** reversible.

### Унаследованные решения (roadmap/prior phases, не переспрашивать)
- **D-04:** Сторонние лайтбокс/зум-библиотеки запрещены roadmap'ом — усиление существующего Base UI Dialog, НЕ замена (иначе умирают delete-flow фото и ⌘K-проба `data-slot="dialog-content"`). Зум — ручные pointer/wheel/pinch-хендлеры внутри `photo-grid.tsx` (или соседнего клиентского модуля). Ноль новых зависимостей фазы.
- **D-05:** Photo-пайплайн не трогается: FULL_EDGE=1600 остаётся — зум до 4x на крупном экране даст мягкие пиксели, осознанный потолок источника (поднятие FULL_EDGE = серверный write-path + ретранскод всего стока, вне клиентской фазы). Роуты выдачи `app/api/attachments` не меняются.
- **D-06:** Disposed-устройство: лайтбокс с зумом работает (фото рендерятся), «Удалить фото» не показывается — существующий canMutate-гейт без изменений (view-only disposed, D-03 фазы 4).

### Claude's Discretion
- Точный множитель двойного клика (~2.5x — середина диапазона; SC лочит только границы [1,4]) и шаг/инерцию колеса.
- Вид skeleton/fade (приглушённый фон в стиле карточки), touch-action CSS стейджа (none при зуме, overscroll-гвард).
- Форма pointercancel-гвада iOS (SC 3 «не залипает в зажатом состоянии») — за исполнителем.
- Счётчик «N из M» в лайтбоксе по паттерну грид-счётчика `photo-grid` (новые русские копии — однострочные шаблонные литералы, smoke-иглы байт-точные).
- Иконки стрелок — lucide-react (ChevronLeft/ChevronRight уже в дереве зависимостей).

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- Состояние `lightboxId`/`lightboxIndex` + `fullUrl()` (`variant=full`) — зум-стейдж садится поверх готовой конструкции, индекс для prev/next уже есть
- Base UI Dialog (`components/ui/dialog.tsx`) — portal, ESC, скролл-лок, focus-trap из коробки; усиливается классами и содержимым, не заменяется
- lucide-react (X уже используется) — ChevronLeft/ChevronRight для стрелок навигации

### Established Patterns
- Клиентский остров + `router.refresh()` после мутаций — delete-флоу не переписывается
- Русские копии рендерятся одним шаблонным литералом (React SSR-сплит текстовых узлов; smoke-ассерты байт-точные) — новые строки лайтбокса так же
- Порталы Dialog стекаются: delete-confirm — сиблинг лайтбокса; новая навигация не лезет в чужой порт

### Integration Points
- `photo-grid.tsx` — грид тумбнейлов + лайтбокс + delete-confirm, всё в одном острове
- ⌘K-палитра (`components/command-palette.tsx`) — проба при открытом лайтбоксе (SC 4), нулевые правки
- `app/api/attachments` — авторизованная выдача через куки-сессию браузера, без изменений

</code_context>
