# Phase 15 — UI Design Contract — Лайтбокс фото устройства

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Sources: `15-CONTEXT.md` (D-01..D-06 locked — использованы дословно; discretion-зоны разрешены в Defaults), `15-RESEARCH.md` (Patterns 1–5, Pitfalls 1–11; два repo-специфичных факта: React `onWheel` пассивен и tailwind-merge сохраняет `sm:max-w-sm`), `REQUIREMENTS.md` (PHOTO-01), `ROADMAP.md` §Phase 15 (SC 1–4 — гейт верификации), approved `04-UI-SPEC.md` §Photos (оригинальный контракт лайтбокса — фаза расширяет его, строки сохраняются байт-точно), `13-UI-SPEC.md` (актуальный destructive-регистр: ровно три красных confirm — удаление фото остаётся нейтральным), implemented code (`app/(app)/(card)/devices/[id]/photo-grid.tsx` — лайтбокс Dialog, canMutate, sibling delete-confirm; `components/ui/dialog.tsx` — data-slot-контракт, не меняется), `app/globals.css` (токены), `components.json` (`registries: {}`).

**Характер фазы:** ZERO новых design-решений на уровне системы — токены, типографика, spacing и accent-дисциплина заморожены. Фаза усиливает единственную поверхность — лайтбокс в `photo-grid.tsx`: панель расширяется до ~max-w-5xl, внутри DialogContent появляется зум-стейдж с жестами, контролы уходят в оверлей поверх стейджа (вне CSS-трансформации, всегда смонтированы). Единственный новый визуальный элемент — рецепт overlay-контрола (`bg-surface/90` + hairline). Accent не расходуется; красный не расходуется. Контракт Dialog не меняется: ESC, скролл-лок, focus-trap, delete-confirm и ⌘K-проба `data-slot="dialog-content"` живут как есть (SC 4).

## Spacing Scale

Inherited from 02-UI-SPEC unchanged: xs 4 / sm 8 / md 16 / lg 24 / xl 32 / 2xl 48 / 3xl 64. Standing exceptions hold (44px min interactive `min-h-11`; 48px header `h-12`; 12px control padding-x `px-3`; half-step 12px `gap-3` allowed).

Phase 15 specifics:
- **Панель лайтбокса:** `max-w-5xl sm:max-w-5xl p-4` — **оба max-w класса обязательны** (Research Pitfall 2: базовый `sm:max-w-sm` в DialogContent переживает `cn("…sm:max-w-sm", "max-w-5xl")`, конфликт резолвится только одноимённым модификатором; `sm:max-w-5xl` безвреден при любой интерпретации каскада). Padding 16px сохранён от 04-UI-SPEC. `showCloseButton={false}` сохранён — close кастомный, поверх стейджа.
- **Зум-стейдж:** `h-[70svh] rounded-lg overflow-hidden` — высота 70svh наследована от 04-UI-SPEC (изображение `max-h-[70svh]`); radius 8px — inner/register (панель 16px, вложенный блок 8px).
- **Оверлей-отступы:** 8px от краёв панели (existing close-рецепт `top-2 right-2` расширяется на все контролы: `top-2 left-2` счётчик, `bottom-2 left-2` удаление, `top-1/2 left-2 / right-2 -translate-y-1/2` стрелки).
- **Иконки-контролы:** `size-11` (44px — standing touch exception), круг `rounded-full`.
- **Грид тумбнейлов не меняется:** `grid grid-cols-3 sm:grid-cols-4 gap-2`, tiles `aspect-square rounded-lg` — фаза не трогает грид (усиление только внутри Dialog).

## Screens & Component Inventory — Лайтбокс (единственная поверхность фазы)

Поверхность одна: лайтбокс внутри `app/(app)/(card)/devices/[id]/photo-grid.tsx` (остров: грид + лайтбокс + sibling delete-confirm). Грид, upload-плитка, delete-confirm и все существующие копии не меняются. Роуты выдачи `app/api/attachments` не меняются (D-05).

### Анатомия DialogContent

```
DialogContent  max-w-5xl sm:max-w-5xl p-4  showCloseButton={false}   ← data-slot="dialog-content" жив (⌘K)
├── DialogTitle sr-only {fileName}                                   ← a11y, без изменений
├── ZoomStage (ключ key={photo.id} — сброс по ремоуту, Pattern 4)
│   └── div h-[70svh] rounded-lg overflow-hidden bg-black/5
│       [touch-action:none] select-none relative
│       └── flex items-center justify-center
│           └── <img> src=variant=full  object-contain max-h-full max-w-full
│               style transform: translate(tx,ty) scale(s)   ← origin center, БЕЗ transition на transform
│               onLoad → fade-in (opacity-0 → opacity-100, duration-200)
│               draggable={false} [-webkit-touch-callout:none] [-webkit-user-drag:none]
└── Оверлей-контролы (сиблинги стейджа, absolute z-10, вне трансформации — D-03):
    ├── счётчик «{n} из {m}»   top-2 left-2   чип h-11 rounded-full bg-surface/90 px-4
    ├── close «X»              top-2 right-2  круг size-11 bg-surface/90  aria-label «Закрыть»
    ├── prev «ChevronLeft»     top-1/2 left-2 -translate-y-1/2  круг size-11
    ├── next «ChevronRight»    top-1/2 right-2 -translate-y-1/2 круг size-11
    └── «Удалить фото»         bottom-2 left-2  h-11 px-4 rounded-lg  (только при canMutate)
```

### Рецепт overlay-контрола (единственный новый визуальный элемент фазы)

| Свойство | Value |
|----------|-------|
| Поверхность | `bg-surface/90` + `ring-1 ring-foreground/10` — белый 90% + hairline; читаем на любом фото (🧪 backstop) |
| Содержимое | `text-ink`; иконки 20px, `aria-hidden` |
| Hover | `hover:bg-surface` (100%) |
| Press | `active:scale-[0.97] duration-100 ease-out` (existing button register) |
| Focus | базовый `focus-visible:ring-3 focus-visible:ring-ring/50` (standing accent focus family — НЕ новый accent) |
| Размеры | иконки-контролы `size-11 rounded-full`; текстовые — `h-11 px-4 rounded-lg` (14/400, secondary-регистр) |
| Disabled | базовый Button-регистр `disabled:pointer-events-none disabled:opacity-50` (инертная стрелка на краях — D-01) |
| Курсор стейджа | при scale>1 `cursor-grab`, во время drag `cursor-grabbing` (Defaults 10) |

Drag-pan физически не начинается на контролах: они сиблинги стейджа, не его дети (D-03). Колесо над контролами инертно — wheel-листенер вешается только на стейдж (Defaults 6).

### Матрица взаимодействия зума (SC 2/3 — ядро контракта)

| Input | Действие | Границы |
|-------|----------|---------|
| Колесо мыши (над стейджем) | зум к позиции курсора: `s' = clamp(s·exp(−ΔY·0.0015), 1, 4)`, deltaMode нормализуется (lines ×16px, pages ×viewport) | clamp [1,4] до пересчёта translate; native non-passive listener (Pitfall 1) |
| Двойной клик / двойной тап (по фото) | тоггл: 1 → 2.5 к позиции курсора; при зуме → 1 | ручная детекция (два pointerup < ~300ms, перемещение < 5px); одиночный клик инертен (D-02) |
| Pinch (2 указателя) | `s' = clamp(scale0·dist/dist0, 1, 4)` к midpoint; при смене числа пальцев базисы переанкерятся (Pitfall 6) | clamp [1,4]; guard `prevDiff > 0` |
| Drag (1 указатель, scale>1) | пан `t = t0 + Δ` | клэмп `|t| ≤ (scaled−stage)/2` по оси; ось без избытка → `t = 0`; при scale=1 пан не начинается |
| `pointercancel` / `lostpointercapture` | полный сброс жестового состояния (iOS pointercancel не залипает — SC 3) | включая переанкер при 1 оставшемся пальце |
| `←` / `→` | prev/next фото; сброс зума и пана на (1x, 0, 0) | не циклическая — инертно на краях; только когда источник события внутри лайтбокса (при открытом confirm или ⌘K — инертно, Pitfall 9) |
| ESC / scrim / ✕ | закрыть | Base UI владеет dismiss и скролл-локом — своих хендлеров НЕ добавлять (Anti-Pattern) |
| Смена фото (любым путём) | сброс (1, 0, 0) + свежий fade-in | key-ремаут `ZoomStage` по `photo.id` (Pattern 4; НЕ setState-в-effect — правило React 19 eslint) |

Навигация prev/next (D-01): стрелки по краям стейджа + клавиши; при M=1 обе стрелки скрыты, счётчик «1 из 1» остаётся (Defaults 4).

### Состояния и поведенческие контракты

- **Загрузка full-варианта (SC 4):** изображение проявляется fade-in (opacity, 200ms) по `onLoad` на приглушённом фоне стейджа `bg-black/5` — пустого мигания нет. `loaded` ставится в event handler'е (легально), не в effect.
- **Зум без анимации transform:** прямое манипулирование — мгновенный отклик; reduced-motion в `globals.css` допускает opacity/color-переходы, transform-переходов на `<img>` не вводить.
- **canMutate = false (disposed, D-06):** «Удалить фото» не рендерится; зум, навигация, ESC работают — view-only просмотр.
- **Delete-confirm:** sibling-портал, рецепт байт-точен (ниже); после подтверждения `router.refresh()` — грид и лайтбокс закрываются как сейчас.
- **⌘K-палитра поверх лайтбокса (SC 4):** лайтбокс рендерится только через обёртку `components/ui/dialog.tsx`; `data-open` эмитится Base UI; нулевые правки палитры.
- **Копии — однострочные шаблонные литералы** (React SSR-сплит; паттерн грид-счётчика). Лайтбокс-контент client-only (портал) — проверка новых копий UAT, не smoke (Research Pitfall 10); smoke-custody остаётся зелёным как регрессия грида/роутов.
