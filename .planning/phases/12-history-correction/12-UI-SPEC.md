# Phase 12 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Sources: `12-CONTEXT.md` (D-01..D-07 — ALL locked, used verbatim; discretion areas resolved in Defaults), `12-RESEARCH.md` (Patterns 1–5, Pitfalls 4/5/6, Russian copy candidates, OQ2/OQ4 adopted as defaults), `REQUIREMENTS.md` (HIST-01..03), `ROADMAP.md` §Phase 12 SC1–5, approved `04-UI-SPEC.md` / `10-UI-SPEC.md` (binding design language, dialog recipes, accent + destructive discipline), implemented code (`app/(app)/(card)/devices/[id]/timeline.tsx` — the surface gaining triggers, `app/(app)/devices/movement-dialogs.tsx` — CONTROL/HINT/ERROR classes + dialog recipe + EmployeePicker, `app/(app)/devices/bulk-dialogs.tsx` — EmployeePicker `onPick` variant, `app/(app)/(card)/devices/[id]/page.tsx` — card layout, `lib/movement-schema.ts` — keystone event dictionary, `app/(app)/devices/actions.ts` — `MovementFormState` + `SAVE_ERROR` family, `components.json` — `registries: {}`).

**Phase character:** ZERO new design decisions at the system level — tokens, typography, spacing, accent discipline are frozen. The timeline becomes a client island whose rows are byte-identical to today plus one trailing action row; two dialogs join the movement-dialog family (fifth and sixth installations of the recipe). The genuinely new semantic is exactly one: the destructive family gains its second member — the red confirm fill moves from «Списать»-only to «Списать» + «Удалить запись» (both irreversible destructions; see Color).

## Spacing Scale

Inherited from 02-UI-SPEC unchanged: xs 4 / sm 8 / md 16 / lg 24 / xl 32 / 2xl 48 / 3xl 64. Standing exceptions hold (44px min interactive height `min-h-11`; 48px header `h-12`; 12px control padding-x `px-3`; `mt-1.5`/`py-2.5`/`px-2.5` forbidden; half-step `mt-3`/`gap-3` = 12px allowed).

Phase 12 specifics:
- **Timeline rows keep the rail geometry byte-exact** (`pl-6 pb-4`, dot `size-2`, 1px connector, `top-[22px]`/`left-[3.5px]` alignment) — the only addition is a trailing action row per event: `mt-2 flex gap-4` (8px above, 16px between the two triggers), the `<li>`'s last element.
- **Row triggers:** quiet text buttons, 14/400, `ink-secondary` → hover `text-ink`, `active:scale-[0.97] duration-100 ease-out`. The visual row stays compact; the 44px touch rule is met by an extended hit-area (`after:`-inset / negative-margin pattern — phase-10 checkbox precedent), not by visible padding.
- **Dialog shells:** `max-w-md p-6`, fields `space-y-4`, label→control `space-y-2`, hint/error paragraphs inside the field stack — byte-parity with all movement dialogs. No scroll cases expected (the largest dialog has 4 fields; standing `max-h-[85svh] overflow-y-auto` rule applies if a planner extension grows it).

Exceptions: none new.

Role assignments for this phase:

- **14/600 (the allowed third weight application):** delete-confirm record label («Выдача»…) mirrors the timeline mini-header; timeline event labels themselves are unchanged.

Record text and hint inside the dialog stay neutral ink — the red marks the *consequence button*, never the content.

## Screens & Component Inventory

Routes touched: the device card only — `app/(app)/(card)/devices/[id]/page.tsx` (the `<Timeline events={…}/>` call becomes the island host; group order and everything else untouched), `timeline.tsx` (→ client island), new `movement-edit-dialogs.tsx` (research structure; planner may inline into `timeline.tsx`), `app/(app)/devices/actions.ts` (+`editMovementAction`/`deleteMovementAction` — non-visual). The other four surfaces (registry row, employee «Техника», dashboard feed/counters, CSV) repaint via `refresh()` only — **zero visual changes** (SC3 is a data-freshness contract, not a layout one).

**Serialization contract (island):** props = `events` — flat per event: `id`, `eventType`, `fromId`, `toId`, `fromName`, `toName`, `comment`, `occurredAtDisplay` («dd.mm.yyyy, hh:mm» via `occurredAtFormat`), `occurredAtDate` (yyyy-mm-dd **computed server-side in DISPLAY_TZ** by the new `occurredAtDateIso` keystone helper — NEVER `toISOString().slice(0,10)`, Pitfall 4) — plus `employees` (active list) serialized **once** (server-dedup-props; dates as strings, no Date objects — vercel server-serialization). The single island is why employees serialize one time regardless of row count (research Alternative rejected: N islands × employee list).

### Timeline rows (D-07)

Visual rendering of the event content is unchanged: 14/600 label · 14/400 secondary meta «{dd.mm.yyyy, hh:mm} · {маршрут}» · comment 14/400 ink when present · «—» dash rule · empty state «История появится после первого действия с устройством.» byte-exact. Every row — **regardless of device status (D-06: disposed included) and position (D-05: «Поступление» included)** — gains a trailing action row (`mt-2 flex gap-4`):

| Trigger | Opens | Needle |
|---------|-------|--------|
| «Исправить» | MovementEditDialog prefilled with THIS record | `data-timeline-edit={movementId}` |
| «Удалить» | MovementDeleteConfirmDialog showing THIS record's text | `data-timeline-delete={movementId}` |

- Uniform recipe on every row — no status matrix, no hiding logic (D-05/D-06 verbatim; a first-record «Поступление» and a disposed device's «Списание» carry the same two triggers).
- The card's custody actions row stays hidden for `disposed` (D-03) — **the timeline's own triggers are the D-06 exception and nothing else unmutes**: no «Редактировать», no «Клонировать», no custody buttons on a disposed card.
- Only one dialog open at a time (natural user behavior; the island may own a keyed open-state `{movementId, mode}` instead of 2N wrappers — planner's choice, behavior locked).

### MovementEditDialog (HIST-01; D-01, D-02)

Recipe: movement-dialog family byte-parity — `max-w-md p-6`, WR-01 split (wrapper stays mounted, `useActionState` in the inner portal-mounted form), echo values on failure, `role="alert"` on form errors, pending-disabled submit. Title «Исправить запись». Context line (HINT_CLASS, 14/400 secondary) above the fields: the record as the timeline renders it — «{label} · {dd.mm.yyyy, hh:mm} · {route}», comment on its own line when present — the TransferDialog «Сейчас у:» precedent; orients the operator when several rows look alike.

Field order — the standing «сотрудник → дата события → комментарий» extended by the master field at the head (D-01 makes type the field that shapes the rest):

| # | Field | Contract |
|---|-------|----------|
| 1 | «Тип действия» | `select`, 7 options labeled by the keystone dictionary (`movementEventLabel` — no parallel labels, anti-pattern: дублирование словаря), prefilled with the record's type, `CONTROL_CLASS`. Includes «Поступление» — `received` exists in seed data and the replay matrix defines its semantics (research verified) |
| 2 | Person slots (D-01) | Rendered ONLY for the selected type: `assigned` → «Сотрудник» (кому); `transferred` → «От кого» + «Кому»; `returned` → «От кого»; `received`/`to_repair`/`from_repair`/`disposed` → no pickers. EmployeePicker = bulk-dialogs **`onPick` variant** (active employees only, Ё/ё fold, value = имя, hidden input carries id, two zero-states byte-exact). **Prefill:** each picker prefills with the record's stored name (OQ2 default: an archived holder keeps name + original id unless replaced — an untouched picker submits the ORIGINAL id even if archived; a new pick must come from active employees, D-02 parity). **Type switch resets slots:** pickers for the newly selected type render empty («Выберите сотрудника»); a missing required slot → inline «Выберите сотрудника». Server derives slots fully from (selected type, whitelisted input) — inapplicable slots NULL (locked semantics) |
| 3 | «Дата события» | `input[type=date]`, `CONTROL_CLASS`, prefilled with the event's **own DISPLAY_TZ day** (`occurredAtDate` prop — the prefill MUST equal the day the timeline displays, Pitfall 4), `max={todayLocal()}` (client convenience; `isNotFutureDate` server-authoritative). Inline errors: «Введите корректную дату» / «Дата не может быть в будущем» (byte-exact family) |
| 4 | «Комментарий» | Optional `input`, `maxLength=500`, placeholder «Номер акта, примечание…», prefilled with the record's comment. **Dispose parity (Pitfall 6):** when the selected type is `disposed`, the field renders as required `textarea` labeled «Причина списания» (placeholder «Например: сгорела после скачка питания», rows 3, error «Укажите причину списания») — same name `comment`, echo survives the shape switch; switching back reverts to the optional input |

Footer: «Отмена» (secondary) + «Сохранить изменения» (accent solid, pending «Сохраняем…»). Success: dialog closes, `refresh()` repaints all five surfaces, operator stays on the card (clone precedent). Failures: field errors inline under controls (`ERROR_CLASS`, `aria-invalid`); form-level `INVALID_CHAIN`/`MOVEMENT_GONE`/generic with `role="alert"` — **everything the operator typed stays** (echo values, Pitfall 5; React-19 form-reset precedent 4886f6a).

Locked-semantics consequence (documented, planner may revisit before build): slots derive from (type, input), so a `to_repair` record that carried «от {держателя}» loses that route segment when edited (its type declares no slots). The timeline route line already renders this state correctly (to_repair without fromName renders nothing).

### MovementDeleteConfirmDialog (HIST-02; D-07)

`window.confirm` is forbidden (anti-pattern; Dialog primitives + {code}-error pattern only — dispose/unarchive precedent).

| Element | Contract |
|---------|----------|
| Title | «Удалить запись?» (question form — «Удалить фото?» precedent) |
| Body — record text (D-07 verbatim: «подтверждением, показывающим текст удаляемой записи») | The record exactly as the timeline renders it: label 14/600 ink, meta 14/400 secondary («{dd.mm.yyyy, hh:mm} · {маршрут}»), comment 14/400 ink when present. Neutral — no red text |
| Hint (14/400 secondary, below the record text) | «Запись будет удалена безвозвратно; статус и держатель устройства пересчитаются из оставшейся истории.» — the D-04 replay made visible (operator learns the status follows the history before confirming) |
| Footer | «Не удалять» (secondary — mirrored negative, dispose/photo precedent) + «Удалить» (solid `#D70015`, white 14/600, hover `bg-destructive/90`, pending «Удаляем…») |
| Success | Dialog closes, `refresh()` repaints; SC2 «запись исчезает из истории» visible immediately |
| Failure | Dialog stays open; `role="alert"` with the same error family as edit (`INVALID_CHAIN` copy / `MOVEMENT_GONE` / generic) — deleting a chain-critical record rejects with zero records written (D-03) |

### What does NOT change

- Tokens, typography, spacing, accent discipline: zero drift; no new npm, no new registry blocks, no new icons.
- Timeline order (`occurredAt DESC, id` tiebreaker — backdated events live their own dates), names-as-text (D-05 anti-analog: timeline names never become links; ids ride the island props for the dialogs only), «—» dash rule, comment-only-when-present.
- Card custody matrix, «Редактировать»/device dialog, «Клонировать», photos, dashboard, registry list, employee card: untouched.
