# Phase 10 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Sources: `10-CONTEXT.md` (D-01..D-06 — ALL locked, used verbatim; the floating panel's position/style and exact copy are declared discretion: «Плавающая панель: позиция/стиль (fixed bottom, Apple-эстетика), точные копи кнопок — ui-phase»), `10-RESEARCH.md` (Patterns 1–3, sibling-checkbox rule, key-reset, Pitfalls 1–8, BulkFormState), `REQUIREMENTS.md` (MOVE-06; §Out of Scope — no cross-page «выбрать всё», no new npm), approved `09-UI-SPEC.md` / `07-UI-SPEC.md` / `04-UI-SPEC.md` (binding design language, dialog recipes, accent discipline), implemented code (`app/(app)/devices/page.tsx` — the row/list surface, `movement-dialogs.tsx` — CONTROL/HINT/ERROR classes, EmployeePicker, pending-copy family, `components/ui/checkbox.tsx` — Base UI wrapper, `components/ui/button.tsx`, `app/globals.css` tokens, `lib/ru.ts` plural helpers, `lib/device-schema.ts` deviceStatusLabel).

**Phase character:** the largest UI delta of the milestone, but ZERO new design decisions: tokens, typography, spacing, accent discipline are frozen; the dialogs are the fourth installation of the movement-dialog recipe; the panel is one new neutral surface. The genuinely new visual devices are exactly two — row checkboxes (first checkboxes in the app UI) and the floating batch panel — both built from existing primitives. Selection never introduces a color the system doesn't have: the checked checkbox fill is the existing accent semantic (`data-checked:bg-primary` → `#0071E3`).

## Spacing Scale

Inherited from 02-UI-SPEC unchanged: xs 4 / sm 8 / md 16 / lg 24 / xl 32 / 2xl 48 / 3xl 64. Standing exceptions hold (44px min interactive height `min-h-11`; 12px control padding-x `px-3` and `mt-3`/`gap-3` allowed; `mt-1.5`/`py-2.5`/`px-2.5` forbidden).

Phase 10 specifics:
- **Row restructure (research sibling rule):** `<li className="flex items-stretch">` → `<RowCheckbox>` cell (`flex w-11 shrink-0 items-center justify-center`, the checkbox centered in a 44px-wide column; the wrapper's `after:-inset` hit-area already extends the target) + `<Link className="flex min-h-11 flex-1 items-center gap-3 px-4 py-2 …">` (existing classes byte-exact, contents unchanged). No new margins — the row keeps its height and rhythm.
- **List card header (tri-state strip):** the card classes move from `<ul>` to a wrapper `<div className="mt-4 divide-y divide-hairline overflow-hidden rounded-2xl bg-white shadow-sm ring-1 ring-hairline">`; first child is the header row `flex min-h-11 items-center gap-3 px-4` (checkbox + label), second child is `<ul className="divide-y divide-hairline">`. Net margins unchanged (`mt-4` stays; the divide does the separating).
- **Floating panel:** `fixed bottom-4 inset-x-0 z-40 flex justify-center pointer-events-none`; inner bar `pointer-events-auto flex items-center gap-3 rounded-2xl bg-white py-2 pr-2 pl-4 shadow-lg ring-1 ring-hairline` (16px off the bottom edge; 8px vertical padding; 16px label-to-first-button; 8px right inset so the quiet link's hit-area breathes).
- **Page spacer:** while `N > 0` the `<section>` gains `pb-24` (96px, multiple of 4 — documented exception) so the panel (~60px + 16px clearance) never covers pagination; removed when selection clears.
- **Dialog shells:** `max-w-md p-6`, header → fields `space-y-4`, label→control `space-y-2`, hint/error paragraphs inside the field stack — byte-parity with all movement dialogs. Report/blocker lists: `max-h-64 overflow-y-auto space-y-2` (20 rows must scroll, not stretch the dialog).
- Empty states, filter bar, pagination: untouched (`mt-4` rhythm preserved).

Exceptions: one new — the conditional `pb-24` page spacer (multiple of 4, documented above).

## Visual Details (inherited + new)

- Radii/motion/shadows: inherited — card and panel 16px (`rounded-2xl`), controls 8px (`rounded-lg`), `shadow-sm` on cards / `shadow-lg` on the floating panel (elevation above content), every interactive element `active:scale-[0.97] duration-100 ease-out`, color-only transitions `duration-150 ease-out`.
- **Checkbox wrapper extension (`components/ui/checkbox.tsx`, the only primitive touched):** render the glyph conditionally — `indeterminate === true` → `MinusIcon`, else `CheckIcon` (usage is always controlled, so the prop is readable in the wrapper). Add `data-indeterminate:bg-primary data-indeterminate:text-primary-foreground` so the mixed state renders the same accent fill as checked — three legible states: empty box / accent+dash / accent+check (iOS-style; A4 discretion). The base `size-4` box, border, focus and hit-area classes are untouched.
- **Row checkbox cell:** `<RowCheckbox deviceId={row.id} model={row.model} />` — client leaf, sibling of the Link (Pitfall 1: never inside the `<a>`); `aria-label={`Выбрать: ${model}`}`; smoke needle `data-device-select={row.id}` (precedent `data-device-assign-id`). Hover background remains the Link's (`hover:bg-page`); the checkbox cell stays neutral — no new hover choreography.
- **Header tri-state (research Pattern 2, controlled):** `checked = selected.size === rows.length && rows.length > 0`; `indeterminate = selected.size > 0 && !allSelected`; click on indeterminate/checked → `new Set()` (частично → снять всё — A4); click on empty → all row ids. Label «Выбрать страницу» is part of the same toggle (`<label>`-wrapped, click = checkbox click). No count in the strip — the panel owns «Выбрано: N».
- **Selection reset (D-01, Pitfall 2):** the provider island mounts with `key={buildDevicesQuery(filters, current)}` — any pagination/filter/search transition changes the key, React unmounts the island, selection is clean. Selection never survives navigation; `query-params.ts` is NOT extended.
- **Panel behavior:** rendered only when `selected.size > 0` (SC 1 «появляется»); conditional render, no animation library. Label `Выбрано: {N}` carries `data-bulk-count={n}`; the bar carries `data-bulk-panel`. Triggers: «Выдать» (default, `size="xl"` — 44px touch rule) opens BulkAssignDialog; «Принять» (secondary, `size="xl"`) opens BulkAcceptDialog; «Снять выделение» clears the Set. The client NEVER disables triggers by row statuses (D-02/anti-pattern 4): eligibility is the server's; a blocked batch is reported, not pre-empted. Checkboxes are enabled on every row including заведомо неeligible (D-01 verbatim).
- **Dialog mechanics (frozen — WR-01 split, byte-parity with movement-dialogs):** wrapper owns trigger-less `open` state (opened from the panel) and stays mounted; `useActionState` lives in the inner form the portal unmounts on close. Hidden `deviceIds` inputs (one per id, `value={id}`). Echo values on failed submit; `role="alert"` on form-level errors; pending-disabled submit against double-click (D-03 second guard is the server's guard-UPDATE).
- **Blocker view (D-03, SC 3):** on `state.blockers` the form STAYS (echo intact, selection untouched — SC 4) and renders above the actions: red intro (ERROR_CLASS, `role="alert"`) «Операция не выполнена: ничего не записано.», one explanation line (14/400 ink-secondary) — assign: «Выдать можно только устройства со статусом «На складе».» / accept: «Принять можно устройства со статусами «Используется» и «В ремонте».» — then the blocker list: one line per unit `{модель} · <mono>{инвентарник}</mono> · {deviceStatusLabel(status)}`, `data-bulk-blockers`, statuses labeled by the ONE keystone dictionary (`deviceStatusLabel`; an absent id renders «Не найдено» — one-off literal, no parallel dictionary). All-or-nothing means the operator never sees a partial state.
- **Success view (D-05/D-06):** on `state.ok` the inner form RENDERS THE REPORT instead of fields (dialog does not close, no redirect, no toast): summary line «Записано: {N}» (14/400 ink) then the per-unit list — one line per unit `{модель} · <mono>{инвентарник}</mono> · {результат}` where результат = «выдано {ФИО}» (assign) / «принято на склад» (returned) / «возвращено из ремонта» (from_repair) — D-05 verbatim. Neutral ink throughout; `data-bulk-report`. The ok-effect calls `provider.clear()` — selection drops ONLY after confirmed success; the panel disappears behind the open dialog. Footer: single «Закрыть» (secondary, DialogClose).
- **Model/inventory for report lines** come from the island's `rows` props mapped by `deviceId` (research Open Question 3: server stays authoritative for fact + eventType, client for display columns it already holds).
- Smoke needles (no component test runner in the repo — UAT via Playwright MCP): `data-device-select={id}`, `data-bulk-panel`, `data-bulk-count={n}`, `data-bulk-blockers`, `data-bulk-report`.

**Interaction contract (page-wide):** check rows (or the header strip) → the panel appears with «Выбрано: N» → «Выдать»/«Принять» opens ONE dialog for the whole batch → submit: either the dialog switches to the neutral report («Записано: N» + одна строка на единицу) and the selection clears, or the form returns blockers (ничего не записано — какая единица и почему) or errors with everything echoed, selection intact. Any navigation (pagination, filter, search) dissolves the selection silently. A double-click cannot double-write: pending-disabled + server guard-UPDATE.
