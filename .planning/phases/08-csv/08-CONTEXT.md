## Phase Boundary

Расширение существующей выгрузки `/api/devices/export`: к текущим 15 колонкам добавляются 4 разреженные конфиг-колонки своего типа (Диагональ / Тип матрицы / Количество портов / Вид) и текстовая колонка «Статус гарантии» из `warrantyState()`. Выгрузка без фильтров = весь парк — уже структурно гарантировано (`exportDevices` полный скан через общий `deviceWhere`), фаза пинит это тестом. Ноль UI, ноль миграций схемы, ноль новых зависимостей.

Не входит: ссылка «Скачать CSV» и имя файла не меняются (кнопка уже в фильтр-баре); пункт «Скачать ведомость» в ⌘K-палитре — Phase 11 (мягкая зависимость); выгрузка сотрудников (не запрошена); любые изменения сайта (`formatWarrantyDate` остаётся dd.mm.yyyy).

<decisions>
## Implementation Decisions

### Конфиг-колонки
- **D-01:** 4 новые конфиг-колонки стоят конфиг-блоком одним куском сразу после «SSD, ГБ». Итоговый порядок колонок: Тип · Модель · Серийный номер · Инвентарный номер · Статус · Держатель · Отдел · RAM, ГБ · RAM апгрейдена · SSD, ГБ · **Диагональ, ″ · Тип матрицы · Количество портов · Вид** · Дата закупки · Стоимость · Поставщик · Гарантия до · Статус гарантии · Заметки. Вся конфигурация устройства — один неразрывный блок.
- **D-02:** Имена CSV-колонок = метки кейстоуна `lib/device-schema.ts` дословно, включая значок дюйма («Диагональ, ″» как на форме). Параллельный CSV-словарь меток не заводится — одна правка в `PER_TYPE_FIELDS` меняет и форму, и файл. — **Reversibility:** reversible — альтернатива «свои короткие CSV-имена» («Матрица», «Порты», «Вид периферии») отклонена как второй источник правды (D-02-дисциплина кейстоуна)

### Статус гарантии
- **D-03:** Словарь состояний: **«Действует / Истекает / Истекла / Без гарантии»** ← `warrantyState()` (ok / warn / expired / none). Без числа дней в тексте — граница видна датой в соседней колонке; вариант «Истекает ≤ 60 дней» отклонён: дублирует `WARRANTY_WARN_DAYS` в строке и ломается при смене константы.
- **D-04:** «Без гарантии» (warrantyUntil null) — текст «Без гарантии», не пустая ячейка: статус-колонка отвечает на вопрос в каждой строке; пустая читается как «забыли заполнить».
- **D-05:** Колонка «Статус гарантии» стоит сразу после «Гарантия до» — дата и её вердикт рядом (пару «Дата закупки … Гарантия до» не разрывать).

### Даты
- **D-06:** «Дата закупки» и «Гарантия до» в файле → ISO `yyyy-mm-dd`. SC 3 выполняется буквально («ISO-даты»); сортировка в Excel локале-независима (лексикографика ISO = хронология; dd.mm.yyyy вне RU-локали датой не распознаётся). Форматтер один на файл — второго способа согласовать даты не существует; сайт не трогается (parity-поверхность SC 1 — статус гарантии, не формат дат).

### Claude's Discretion
- `exportDevices` расширяет SELECT четырьмя полями (`screenDiagonal`, `panelType`, `portCount`, `peripheralKind` — колонки уже есть в таблице, миграций ноль)
- Разреженность: у чужих типов ячейки пустые (RAM/SSD уже так; «Вид» заполняется только у периферии и т.д.)
- Размещение файлового ISO-форматтера и словаря статуса (рядом с роутом экспорта / в lib — но словарь статуса один)
- Тест-матрица (vitest, без новых зависимостей): sparse-заполнение по всем 4 типам; parity статус↔`warrantyState`↔фильтр на границах (0 / 60 / 61 день, null); ISO-формат дат; новые ячейки под `esc()`-гвардом (инъекция уже покрыта `tests/csv-export.test.ts` — расширить на новые колонки)
- Имя файла, `csvResponseHeaders`, ссылка в фильтр-баре — не меняются

</decisions>

## Existing Code Insights

### Reusable Assets
- `buildCsv` + `esc` (`lib/csv.ts`) — все новые ячейки автоматически под TAB-гвардом CWE-1236: SC 3 «инъекция невозможна» закрывается построением, вторых путей в файл нет
- `warrantyState` (`lib/warranty.ts`) — единственный расчёт статуса: parity с цветом сайта по построению (тот же модуль, что фильтр и подсветка)
- `PER_TYPE_FIELDS` (`lib/device-schema.ts`) — метки и набор конфиг-полей: SELECT и HEADER сверяются с ним, не с ручным списком
- `csvResponseHeaders` + ссылка «Скачать CSV» в фильтр-баре — транспорт не меняется вообще

### Established Patterns
- Один парсер + один предикат (`parseDevicesSearchParams` → `toDeviceListFilters` → `deviceWhere`): экспорт = страница, дрейф не представим (WR-01; SC 2 структурно закрыт, тест пинит число строк)
- `requireSession()` первым действием роута — SC 4 уже в коде, не переписывать
- Pure lib-модули без фреймворк-импортов — файловый форматтер и словарь статуса пишутся в той же дисциплине (vitest зовёт напрямую)

### Integration Points
- `exportDevices` SELECT: + 4 конфиг-поля (в таблице уже есть, миграций ноль) → `DeviceExportRow` расширяется
- `route.ts` cells-маппинг: + 5 колонок в позициях D-01/D-05, ISO-форматтер (D-06), словарь статуса (D-03/D-04)
- Phase 11 (мягкая зависимость): пункт «Скачать ведомость» в палитре ведёт на этот же роут — контракт роута не менять

<specifics>
## Specific Ideas

- «Статус-колонка отвечает в каждой строке» — принцип D-04: никаких пустых статус-ячеек
- ISO-даты — единственное решение, меняющее видимое поведение существующих колонок файла; осознанно, ради SC 3 и локале-независимой сортировки
- Словарь статуса без числа дней — чтобы строка не дублировала `WARRANTY_WARN_DAYS`

</specifics>
