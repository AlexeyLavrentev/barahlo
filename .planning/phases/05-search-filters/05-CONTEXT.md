<decisions>
## Implementation Decisions

### Поведение поиска
- **D-01:** Поиск живой — результаты обновляются по мере ввода (короткий дебаунс ~300 мс, затем серверный запрос через URL searchParams), с первого символа. [user: выбрано явно]
- **D-02:** Поля поиска строго FIND-01: серийник, инвентарник, модель. Имя держателя НЕ ищется — «вся техника Иванова» живёт в карточке сотрудника. [user: выбрано явно]
- **D-03:** Сортировка найденного — та же русская сортировка по модели, что и весь реестр (стабильный порядок в любых фильтрах); «релевантность» не строится. [user: выбрано явно]
- **D-04:** Пустой результат: заголовок «Ничего не найдено», подсказка проверить раскладку (набранное кириллицей «С123» находит «C123») и кнопка «Сбросить фильтры» — один клик обратно к полному списку. [user: выбрано явно]
- **D-05:** При активном поиске/фильтрах подзаголовок списка показывает «Найдено: N устройств» вместо общего счётчика. [user: выбрано явно]

### RAM-фильтр (FIND-02)
- **D-06:** Семантика — явный флаг `ramUpgraded` (галка в форме ноутбука), НЕ сравнение с номинальной RAM модели. Блокер из STATE (фаза 3) закрыт: справочник номиналов не заводим, ноль миграций. [user: выбрано явно]
- **D-07:** «Без апгрейда» = `ramUpgraded ≠ 1` внутри типа «ноутбук»: входят и явное «нет» (0), и незаполненное (null) — галка ставится только по факту апгрейда. [user: выбрано явно]
- **D-08:** Быстрый фильтр — постоянный чип-тумблер над списком рядом с поиском: один клик фильтрует; активация чипа выставляет тип «ноутбук» (смена типа на не-ноутбук чип сбрасывает). [user: выбрано явно]

### Фильтры (FIND-03)
- **D-09:** Фильтр по отделу = устройства, чей текущий держатель состоит в этом отделе. Устройства на складе (держателя нет) в фильтр не попадают — склад виден через статус-фильтр. Техника у архивного сотрудника входит в его отдел (держатель есть — приёмка единицы не теряется). [user: выбрано явно]
- **D-10:** Фильтр статуса — single select с опцией «Все статусы» (без мульти-выбора; комбинируемость FIND-03 — про разные измерения). [user: выбрано явно]
- **D-11:** Списанные устройства в реестре по умолчанию видны (дефолт фазы 3 не меняется); поиск по серийнику находит их сразу. [user: выбрано явно]
- **D-12:** Все фильтры — одной строкой над списком: поиск + тип + статус + отдел + гарантия + RAM-чип; без поповера «Фильтры». [user: выбрано явно]
- **D-13:** Контрол выбора отдела — Select (не combobox): Base UI combobox уже дважды кусался (value-семантика, bb5674e/7e400c9), select надёжен и есть образец в type-filter.tsx. [user: выбрано явно]
- **D-14:** Отдельных чипов активных фильтров нет — селекты сами показывают значения; сброс через «Все …» в селектах и кнопку «Сбросить фильтры» в пустом состоянии (D-04). [user: выбрано явно]

### Гарантия (WAR-01 + гарантийное окно)
- **D-15:** Гарантийный фильтр — пресеты: «истекает ≤ 30 дней», «истекает ≤ 60 дней» (главный из FIND-03), «истекла». Произвольного N дней нет. [user: выбрано явно; ответ «1» текстом после двух пустых AskUserQuestion]
- **D-16:** Подсветка — цветная дата гарантии (зелёный / жёлтый «< 60 дней» / красный «истекла») в трёх местах: вторая строка каждой row реестра («гар. до 12.03.2027»), карточка устройства, список выданной техники на карточке сотрудника. WAR-01 «card and lists» — буквально, один расчёт/компонент на все места. [user: выбрано явно]
- **D-17:** Цвета: жёлтый #FF9500 (apple orange), красный #D70015 — тот же семантический красный, что у «Списать» (резерв #D70015 — про кнопки-действия, бейджи даты его не ломают; один красный в системе). [user: выбрано явно]

### CSV-экспорт (решение roadmap, отданное на эту фазу)
- **D-18:** CSV-экспорт входит в фазу: кнопка над списком устройств, выгружает ПОЛНЫЙ результат текущих фильтров/поиска (все страницы), UTF-8 BOM + разделитель «;» — Excel/Numbers открывают из коробки; защита от «параллельной таблицы» мимо реестра. [user: выбрано явно]

### Claude's Discretion
- Механика поиска: нормализация запроса через `lib/normalize.mjs` (trim, upper, гомоглифы) + сравнение по normalized-колонкам; по модели — свёртка на лету при запросе (сотни строк — скан ок)
- URL-синхронизация всех фильтров: полный query string, сброс страницы при смене любого фильтра (паттерн фазы 3), живой поиск — дебаунс поверх router.push
- Пороги гарантии: сравнение дат в DISPLAY_TZ=Europe/Moscow (урок CR-01, 1a31814); `warrantyUntil = null` = «без гарантии» — не подсвечивается, в гарантийные фильтры не попадает
- Копи пустых состояний и подсказок — в рамках копи-контракта UI-SPEC
- Состав колонок CSV и имя файла (дата в имени)
- Гомоглиф-фикстура typing-теста (блокер STATE: собрать С↔C, О↔O… — приём нормализации подтверждён только практикой)
- Seed: расширить до сотен устройств для приёмки UI-03 (сейчас 80)
- Представление галки ramUpgraded в форме не меняется (фильтр D-07 покрывает и 0, и null)

- vitest + temp-SQLite, smoke-паттерн — тесты фильтров на queries-модуле

### Established Patterns
- URL-driven состояние: searchParams валидируются на сервере (isDeviceTypeKey/Number-guard), ссылки строят полный query string, смена фильтра → page=1
- Server Components: requireSession → queries → render; клиентские острова только для контролов (фильтр, дебаунс-инпут, чип)
- Русские строки инлайн; sort recipe `replace(replace(...,'Ё','Е'),...)` + id tiebreaker

### Integration Points
- Отдел: `devices.currentEmployeeId → employees.departmentId` (join уже есть в listDevices для holder)
- Списанные и склад: devices.status CHECK ('in_stock','assigned','repair','disposed') — фильтр статуса поверх
- `attachments` covers в listDevices — не сломать при расширении where
- CSV: новый route за default-deny периметром (api/* уже прикрыт прокси)
- Seed: `scripts/seed.mjs` (80 устройств) — расширить до сотен для UI-03
