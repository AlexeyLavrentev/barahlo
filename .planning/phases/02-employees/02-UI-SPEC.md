## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, badge padding-y, inline emphasis gaps |
| sm | 8px | Compact element spacing, input padding-y, stacked form rows |
| md | 16px | Default element spacing, list card padding-x, dialog field gaps |
| lg | 24px | Card padding (`p-6`), section gaps |
| xl | 32px | Page vertical rhythm, login card padding |
| 2xl | 48px | Header height, major section breaks |
| 3xl | 64px | Page-level top spacing on sparse screens |

Exceptions:
- **44px minimum height** for list rows and interactive controls (`h-11`) — Apple touch-target guideline; serves both desktop comfort and phone use (responsive web is in scope).
- **Header bar fixed at 48px** (`h-12`).
- **12px control padding-x** (`px-3`) for inputs/buttons and card inner gaps — off the 8-point ladder but on the 4px grid (12 = 3×4): Tailwind-native `px-3` keeps control hit areas comfortable without inflating to 16px. Every other spacing value must come from the scale above.
- Tailwind classes producing 6px/10px (`mt-1.5`, `py-2.5`, `px-2.5`) are **forbidden in new code**; the existing login screen is normalized to this scale during this phase (вход is an in-phase screen per roadmap success criterion 3).

## Typography

| Role | Size | Weight | Line Height | Tracking | Tailwind |
|------|------|--------|-------------|----------|----------|
| Label / secondary | 14px | 400 | 1.45 | 0 | `text-sm` |
| Body | 16px | 400 | 1.5 | 0 | `text-base` |
| Heading | 20px | 600 | 1.2 | -0.01em | `text-xl tracking-tight` |
| Display | 28px | 600 | 1.2 | -0.02em | `text-[28px] tracking-[-0.02em]` |

Weight set is exactly two: **400 (regular) + 600 (semibold)**. No 500 anywhere — replace existing `font-medium` occurrences during normalization.

Role assignments for this phase:
- **Display (28/600):** employee card title (the employee name), «Учёт техники» login wordmark.
- **Heading (20/600):** page titles («Сотрудники»), dialog titles, card section headers («Техника»).
- **Body (16/400):** employee name in list rows, text inputs (16px prevents iOS input zoom), dialog body copy.
- **Label (14/400):** department in rows, form labels, meta, pagination, segmented control, secondary buttons.
- **Controls:** primary/confirm button text = 14px/600; secondary buttons = 14px/400.

## Color

Light theme only (see Design System). Declare in `globals.css`:

```css
:root {
  --color-page: #F5F5F7;          /* 60% */
  --color-surface: #FFFFFF;       /* 30% */
  --color-ink: #1D1D1F;           /* text primary */
  --color-ink-secondary: #6E6E73; /* text secondary */
  --color-hairline: #D2D2D7;      /* 1px borders */
  --color-accent: #0071E3;        /* 10% */
  --color-destructive: #D70015;   /* reserved */
}
```

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F5F5F7` | Page background; row hover fill on white cards |
| Secondary (30%) | `#FFFFFF` | Cards, list container, sticky header bar, dialogs, segmented-control active pill |
| Text primary | `#1D1D1F` | Names, values, headings |
| Text secondary | `#6E6E73` | Department, form labels, placeholders, meta, pagination, icons-secondary |
| Hairline | `#D2D2D7` | 1px card rings, input borders, separators |
| Accent (10%) | `#0071E3` | See reserved list below — nowhere else |
| Destructive | `#D70015` | **Not used in Phase 2.** Archive is reversible (D-02), so its button and confirmation are neutral — apple-design principle 2 (red only for genuinely destructive). Reserved for Phase 4 «Списать» |

Accent reserved for exactly three things:
1. Primary CTA button «Добавить сотрудника» (create) and the edit-dialog primary «Сохранить изменения» (solid `#0071E3`, white 14/600 text, hover `#0077ED`).
2. Focus state: input/combobox focus ring `ring-2 ring-[#0071E3]/30` + focused border `#0071E3` (replaces the Phase 1 black focus).
3. Combobox: checkmark and highlight of the selected department row.

Hover darkening for accent button only: `#0077ED`. Never accent text on gray, never accent badges, never accent the segmented control (its selected state is the white pill, not color).

## Visual Details (radii, elevation, motion)

- Radii: cards/panels/dialogs **16px** (`rounded-2xl`), controls/inputs/buttons/segmented **8px** (`rounded-lg`), badges/pills **full** (`rounded-full`). 1px hairlines only; shadows are whisper-quiet: `shadow-sm` on cards, none on inputs.
- Press feedback (apple-design §1): every button/row gets `active:scale-[0.97]` with `transition duration-100 ease-out` — response on pointer-down, not release.
- Hover: list rows `bg-[#F5F5F7]` fade 150ms ease-out; secondary buttons `bg-black/[0.03]`.
- Dialog (create/edit/archive confirm): scrim `rgba(0,0,0,0.3)` fade + panel `scale 0.96→1` 200ms ease-out, enter and exit along the same path (apple-design §7).
- Combobox popover: opacity + slight scale from trigger origin (`transform-origin: top`), 150ms.
- Segmented control: active white pill slides 200ms ease-out.
- **No springs this phase** — no drag/flick gestures exist. (If any appear later: damping 1.0, response 0.3 per apple-design.)
- `prefers-reduced-motion: reduce` → all of the above become opacity cross-fades ≤200ms, no scale/slide. `prefers-reduced-transparency: reduce` → header becomes solid white, `backdrop-filter: none`.

### App shell (established this phase, inherited by 3–6)

- Sticky top bar, 48px, translucent material per apple-design §12: `bg-white/70 backdrop-blur-md`, 1px bottom hairline `border-black/5`; content scrolls beneath it.
- Left: «Учёт техники» (14/600, ink). Center-left nav: «Сотрудники» (14/400; active = ink, inactive = `#6E6E73`). Right: «Выйти» (14/400, `#6E6E73`, hover ink) — existing logout action.
- Content column: centered, `max-w-3xl` (list), `max-w-2xl` (employee card); `px-4` mobile / `px-6` desktop, `py-8`.
- `(app)/page.tsx` stub becomes a redirect to `/employees` (planner confirms route choice).

## Defaults Assumed (discretion resolutions — audit trail)

CONTEXT.md mode is `--auto`; this subagent cannot prompt the user. Every gap below was resolved to a documented default within CONTEXT.md's declared discretion areas or apple-design guidance; the planner may override before execution.

| Question | Default chosen | Basis |
|----------|----------------|-------|
| Inline department creation form (D-03 discretion: «dropdown+кнопка vs combobox») | Combobox (popover + command) with type-to-create option «Создать „X“» | D-03 names combobox; one control, zero extra buttons — apple-design simplicity |
| Create/edit surface (not locked upstream) | Centered dialog `max-w-md`, not a separate page | 2 fields only; the full-page form pattern is established in Phase 3 for the device form |
| Sort (CONTEXT discretion) | По имени А→Я, `Intl.Collator('ru')` | CONTEXT names asc-by-name as default |
| Pagination markup (CONTEXT discretion) | Prev/next + «Страница N из M», 20/page, no page numbers | Up to 10 pages at 200 employees; numbers add noise, not value |
| Dark mode (unaddressed upstream) | Light only; dark block removed from `globals.css` | Not in any requirement; halves visual surface; cheap to revisit |
| Body font (unaddressed upstream) | System stack replacing Geist Sans | Geist has no Cyrillic subset; apple-design §15 |
| Archive button color | Neutral, not red | Archive is reversible (D-02); red reserved for real destructive actions |
| Card action labels are terse single verbs («Редактировать», «Архивировать», «Разархивировать») without a noun | Deliberate terseness kept: the actions row sits directly beneath the 28px employee name, which supplies the noun; the archive confirmation repeats the full noun («Архивировать сотрудника?») | apple-design favors short contextual labels on a card; checker recommendation resolved via context, not longer labels |
