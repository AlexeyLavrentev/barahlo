# Phase 9 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Sources: `09-CONTEXT.md` (D-01..D-08 — ALL locked, used verbatim; the dialog copy itself is declared discretion: «Копи диалога… — ui-контракт в планах, Apple-стиль»), `09-RESEARCH.md` (Pattern 5 CloneDialog каркас, Pattern 4 nextInventoryNumber, action contract, A1/A3 assumptions, Open Questions 1–2), `REQUIREMENTS.md` (REG-06; §Out of Scope — no new npm), approved `07-UI-SPEC.md` / `04-UI-SPEC.md` (binding design language and dialog recipes), implemented code (`app/(app)/devices/movement-dialogs.tsx` — the dialog mechanics source, `device-actions.tsx` — action-row invariants, `app/(app)/(card)/devices/[id]/page.tsx` — the card surface, `app/globals.css` tokens, `lib/ru.ts`, `device-dialog.tsx` — mono/masked-input recipes).

**Phase character:** ONE new dialog and ONE new button on an existing card — the visual delta is a single secondary trigger in the card's action row, one `max-w-md` dialog with two fields, and one inline success line. Everything else is inheritance: tokens, typography, spacing, accent discipline, dialog mechanics (useActionState + useCloseOnOk + WR-01 split + echo values) are all frozen recipes from phases 2–5. This is the third dialog-family installation; nothing about the design system changes.

## Spacing Scale

Inherited from 02-UI-SPEC unchanged: xs 4 / sm 8 / md 16 / lg 24 / xl 32 / 2xl 48 / 3xl 64. Standing exceptions hold (44px min interactive row height `min-h-11`; 12px control padding-x `px-3`; 12px `mt-3`/`gap-3` allowed; `mt-1.5`/`py-2.5`/`px-2.5` forbidden).

Phase 9 specifics (all inside the established dialog recipe — no new rhythm):
- **Action row:** «Дублировать» renders inside the existing `mt-6 flex flex-wrap gap-2` row on the card — it inherits the 8px `gap-2`; no wrapper, no new margins.
- **Dialog shell:** `max-w-md p-6` (byte-parity with all six movement dialogs); header → fields stack `space-y-4` (16px); each field block `space-y-2` (label → control, 8px); hint/error paragraphs render inside the field's `space-y-2` stack (8px below the control — movement-dialogs precedent).
- **Success line:** `mt-2` (8px, on-grid) below the action row — the only new margin on the card.
- Count input width: `w-24` (96px, multiple of 4) — a number does not need the full column; the inventory input is `w-full` like every text field in dialogs.

Exceptions: none new.

Quiet ink is the Apple-style confirmation.
- The count input, inventory input, hints, placeholders — neutral.

## Visual Details (inherited + new)

- Radii/motion/shadows: inherited — dialog 16px card radius, controls 8px (`rounded-lg`), every interactive element `active:scale-[0.97] duration-100 ease-out`, color-only transitions `duration-150 ease-out`. Overlay/portal behavior is the Dialog primitive's, unchanged.
- **Dialog mechanics (frozen — research Pattern 5, byte-parity with movement-dialogs):** WR-01 split — the `CloneDialog` wrapper owns the trigger and `open` state and STAYS mounted; `useActionState` lives in an inner `CloneDialogForm` that the portal unmounts on close, so every dialog session starts from a clean state. `useCloseOnOk(state, onDone)` closes on success. Uncontrolled inputs + `defaultValue`; on failed submit the action echoes submitted values back into the fields (React 19 reset pattern, 4886f6a). Errors render `role="alert"`; field errors render under their control with `aria-invalid` on the input.
- **Trigger:** `DialogTrigger render={<Button variant="secondary" size="xl" data-device-clone-id={deviceId} />}` — the `data-device-clone-id` attribute is the smoke-test needle (precedent: `data-device-assign-id` etc.).
- **Action-row placement (D-01 «рядом с custody-действиями» — resolved):** «Редактировать» → **«Дублировать»** → custody buttons (status matrix) → «Списать» last. The custody island's own invariant — «Списать is always LAST, the destructive step sits at the end of every row» — outranks the research ASCII diagram's «custody-кнопки · Дублировать» ordering; the clone button therefore mounts in the card page BETWEEN `DeviceDialog` and `DeviceActions`, not inside the custody island (clone is card-level, not a custody transition, and must render for ALL non-disposed statuses uniformly).
- **Disposed cards (A1):** the page hides the ENTIRE action row for `disposed` — «Дублировать» inherits that hiding; cloning a written-off purchase is unavailable (research Open Question 1 recommendation; one-line retarget if the owner ever wants otherwise).
- **Suggestion mechanics (D-02):** the dialog receives the original's RAW `inventoryNumber` as a flat serializable prop; the wrapper computes `suggested = nextInventoryNumber(inventoryNumber)` client-side (the lib function must be client-safe — no server-only imports) and passes it as the field's `defaultValue`. The field is a plain editable input: the operator may overwrite, clear, or keep it. **No live sequence preview in the dialog** — the server authoritatively recomputes the N-number sequence from the submitted start (client value is only an editable starting point); a client-side preview list would be a second source of truth and a drift surface.
- **Empty suggestion (SC 3):** pattern unrecognized (no trailing number) or original inventory empty → `defaultValue` is `''` — the field renders with its placeholder and nothing is ever auto-appended. No hint difference, no disabled state: an empty inventory for copies is legal (NULL/NULL pairs).
- **Count field:** `type="number" inputMode="numeric" min={1} max={100} step={1} autoComplete="off"`, `defaultValue={1}` (D-01 default) — byte-parity with the device-dialog «Стоимость» numeric recipe plus `max`. DOM `min`/`max` are client convenience only; the server re-validates 1..100 via zod (D-03).
- **Inventory field:** `type="text" autoComplete="off" maxLength={80}` (DOM mirror of the zod cap), `className={`${CONTROL_CLASS} font-mono`}`, `placeholder="Из 1С, если присвоен"` (byte-exact device-dialog vocabulary), `defaultValue={suggested}`.
- **Success confirmation (D-07, research Open Question 2 — resolved):** NO toast (the repo has no toast primitive and gains none). The wrapper stores the created count delivered by `onDone(created)` and renders an inline line below the action row: `mt-2 text-sm text-ink`, `data-clone-created={n}` as the smoke needle. It persists until the dialog is opened again (cleared on open) or the page changes; `refresh()` in the action repaints the server tree but the island persists, so the message survives the re-render. Staying on the original's card is the whole point (D-07) — no navigation to the copies.
- **Success message ownership:** `onDone` signature for the clone form is `(created: number) => void` (divergence from the movement dialogs' `onDone: () => void`, which carry nothing back) — the form reads `state.ok`/`state.created` in `useCloseOnOk` and hands the count up.

The migration (0001 + runner) is non-visual. List page, filters, search, employee surfaces, photos, timeline: unchanged.

| Screen / component | Contract |
|--------------------|----------|
| Card action row | Order fixed: «Редактировать» (existing DeviceDialog trigger) · **«Дублировать»** (NEW, secondary, `data-device-clone-id`) · custody matrix (DeviceActions, untouched) · «Списать» stays last inside the matrix. Whole row hidden for `disposed` (A1). `flex-wrap` already handles up to six buttons on narrow screens |
| `CloneDialog` (new, wrapper) | Stays mounted; owns `open` state and the success line. Props: `deviceId: number`, `inventoryNumber: string \| null` (RAW — never normalized, Pitfall 4). Computes `suggested` via `nextInventoryNumber`. Renders trigger + `DialogContent className="max-w-md p-6"` + `DialogHeader/DialogTitle`. Clears the success line when opening |
| `CloneDialogForm` (new, inner) | `useActionState(cloneDeviceAction, {})` + `useCloseOnOk(state, (n) => onDone(n))`. `form className="space-y-4"`; hidden `deviceId`; fields per the anatomy above; `state.error` → `role="alert"` red paragraph; footer `DialogFooter`: «Отмена» (secondary, DialogClose) + primary submit pending-aware: label «Дублировать», pending «Создаём копии…», `disabled={pending}` |
| `cloneDeviceAction` (new, non-visual) | Contract per research Code Examples: requireSession first, zod white-list `{ deviceId int+, count int 1..100, inventoryNumber ≤80 optional }`, echo values, `uniqueFieldError` mapping (collision → inventoryNumber field error), `refresh()`, returns `{ ok: true, created }`. Empty-string inventory → `null` BEFORE the query layer (Pitfall 5) |
| Success line (wrapper-owned) | `mt-2 text-sm text-ink`, text «Создано {pluralDevices(n)}» — 1 устройство / 2 устройства / 5 устройств; `data-clone-created={n}`. Rendered only after a confirmed success; removed on next dialog open |
| `nextInventoryNumber` (new lib, non-visual) | Pure function on RAW input; `''` for null/empty/no-trailing-number (SC 3 — silent, no invention). PadStart preserves zero padding; rollover `AB-099`→`AB-100` widens naturally. Shared by client prefill and server sequence — one source of truth (D-02) |

**Interaction contract (page-wide):** open → edit at most two fields → submit → either the dialog closes and a quiet inline line confirms («Создано N копий»), or the dialog stays open with red field/form errors and everything the operator typed echoed back. Mid-batch failure is invisible as a partial state — the transaction rolls back to zero copies (SC 1), and the dialog reports the error; the card never shows a "half-cloned" state.

| interaction | dialog reuse race (open → close → open) | ✅ covered | WR-01 portal unmount resets form state per session; wrapper clears the previous success line on open |
| long-text | 80-char inventory in `max-w-md` dialog | 🧪 backstop | Held-out visual test: an 80-char mono value fits the input (native scroll) and the error/hint lines wrap inside the dialog without breaking the recipe |
