## Spacing Scale

Inherited from 02-UI-SPEC unchanged: xs 4 / sm 8 / md 16 / lg 24 / xl 32 / 2xl 48 / 3xl 64. All existing exceptions stand (44px min interactive height `min-h-11`; 48px header `h-12`; 12px control padding-x `px-3`; half-step classes `mt-1.5`/`py-2.5`/`px-2.5` forbidden).

Phase 3 specifics:
- **Two-line device rows:** `min-h-11 px-4 py-2` — both values on-scale; the 44px minimum is preserved by content + padding, no new exception.
- **Device form dialog:** same `max-w-md p-6` as phase 2; the form is taller than the employee form (8–11 fields), so the dialog body scrolls: `max-h-[85svh] overflow-y-auto` on the content wrapper. Field groups separated by `space-y-4`, group header to first field `space-y-2` (same as employee dialog rhythm).
- **Card field rows:** `min-h-11 px-4 py-2`, hairline separators (`divide-y divide-hairline`) — identical recipe to list rows so list and card read as one system.
- **Skeleton rows (list loading):** height 56px (`h-[60px]`) — matches the two-line row height; same `bg-black/5 rounded-lg` recipe as phase 2, 5 rows.

## Typography

Inherited unchanged — exactly 4 sizes, exactly 2 weights (400 + 600; no 500 anywhere):

| Role | Size | Weight | Line Height | Tracking | Tailwind |
|------|------|--------|-------------|----------|----------|
| Label / secondary | 14px | 400 | 1.45 | 0 | `text-sm` |
| Body | 16px | 400 | 1.5 | 0 | `text-base` |
| Heading | 20px | 600 | 1.2 | -0.01em | `text-xl tracking-tight` |
| Display | 28px | 600 | 1.2 | -0.02em | `text-[28px] tracking-[-0.02em]` |

Role assignments for this phase:
- **Display (28/600):** device card title = the model name.
- **Heading (20/600):** page title «Устройства», dialog titles, empty-state headings, card section headers («Основное», «Закупка», «Характеристики типа», «История перемещений», «Фото»).
- **Body (16/400):** model name in list row line 1, all input/select/textarea text (16px prevents iOS zoom), card field values, card meta line, notes text.
- **Label (14/400):** list row line 2 (тип · серийник · инвентарник · держатель), form labels, hints, placeholders, filter trigger, pagination, status pill text, secondary buttons.
- **In-dialog group headers:** 14/600 ink (`text-sm font-semibold text-ink`) — smaller than card section headers on purpose: a dialog is a form, not a page.
- **Mono numerals:** серийник and инвентарник render `font-mono text-sm` (14/400) in list line 2 and card values. RAM/SSD/цена stay in the system font (they are quantities, not identifiers).
- **Controls:** primary button 14/600; secondary buttons 14/400 (unchanged).

## Color

Inherited from `globals.css` verbatim (already implemented — do not redefine):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F5F5F7` (`bg-page`) | Page background; row hover fill on white cards |
| Secondary (30%) | `#FFFFFF` (`bg-surface`) | List card, card sections, dialog, header bar, select popover |
| Text primary | `#1D1D1F` (`text-ink`) | Model, values, headings |
| Text secondary | `#6E6E73` (`text-ink-secondary`) | Row line 2, form labels, hints, placeholders, pagination, chevron `#C7C7CC` |
| Hairline | `#D2D2D7` (`ring-hairline` / `divide-hairline`) | Card rings, row separators, input borders |
| Accent (10%) | `#0071E3` (`bg-accent`) | Reserved list below — nowhere else |
| Destructive | `#D70015` | **Still unused as a fill.** Appears only as inline validation text (error semantics, per phase 2). Phase 4 «Списать» keeps the reservation |

Accent reserved for exactly three things (phase 3 extension of the phase 2 list):
1. Primary CTA «Добавить устройство» and the dialog primary («Добавить устройство» create / «Сохранить изменения» edit) — solid `#0071E3`, white 14/600, hover `#0077ED`, `active:scale-[0.97]`.
2. Focus state: input/select/textarea focus ring `ring-2 ring-accent/30` + focused border `#0071E3`.
3. Select affordances: the checkmark and highlight of the selected option in the type filter and the «Вид» периферии select (same semantics the combobox checkmark had in phase 2).

Explicitly NOT accent: status pills (neutral `bg-black/5` — colored statuses arrive with warranty/status semantics in phases 4–5), the type filter trigger, card section headers, mono serial numbers, the «RAM апгрейдена» checkbox (neutral track; checked = ink fill per shadcn default retargeted to `--primary` — acceptable as a control fill, never used decoratively).

## Visual Details (inherited + new)

- Radii/motion/shadows: inherited unchanged — cards/panels/dialogs 16px (`rounded-2xl`), controls 8px (`rounded-lg`), badges full; `shadow-sm` on cards, none on inputs; every button/row `active:scale-[0.97] duration-100 ease-out`; dialog scrim fade + panel scale 0.96→1 200ms ease-out; select/checkbox popover opacity+scale 150ms; reduced-motion/transparency handling already global in `globals.css`.
- **Select popover** (type filter, «Вид»): same entrance as the combobox popover — opacity + slight scale from trigger origin, 150ms; item highlight `bg-accent/10` text-ink, checkmark accent.
- **Dialog scroll:** when the device form exceeds the viewport, the body scrolls inside the 16px-radius panel; the footer («Не сохранять» / primary) stays pinned at the bottom of the panel — never scrolls away.
- **Status pill:** `rounded-full bg-black/5 px-2 py-1 text-sm text-ink-secondary` — the exact «В архиве» recipe from phase 2, reused for all four statuses. One pill per row, on list line 1 (right, before chevron) and in the card «Основное» group.

### App shell change (one deliberate edit)

The 48px bar gains a second nav item; nav order puts the core entity first: **«Устройства» · «Сотрудники»** (14/400; active route = `text-ink`, inactive = `text-ink-secondary`, hover → ink — the active/inactive rule phase 2 declared but only one item could express). `app/(app)/page.tsx` redirect switches `/employees` → `/devices` (devices are the product's center of gravity; planner confirms). Both changes are one-screen edits in `app/(app)/layout.tsx` / `page.tsx`.

## Defaults Assumed (discretion resolutions — audit trail)

CONTEXT.md mode is `--auto`; this subagent cannot prompt the user. Every gap below was resolved to a documented default within 03-CONTEXT.md's declared discretion areas («точная группировка полей в карточке и порядок колонок списка», «формат отображения даты/цены (ru-RU Intl)», «подсказка про инвентарник-вместо-серийника») or by strict inheritance from the approved 02-UI-SPEC; the planner may override before execution.

| Question | Default chosen | Basis |
|----------|----------------|-------|
| Device form surface: phase 2 spec once «reserved the page-pattern for Phase 3's device form», but D-06 locks «тот же диалог, что создание, в edit-режиме (паттерн фазы 2)» | **Dialog wins** (later, phase-specific decision): one dialog component, create + edit modes, exactly the employee-dialog mechanics | D-06 (locked) supersedes the phase 2 placeholder note |
| List columns (6) vs phase 2 single-line rows | Two-line row: модель + статус on line 1; тип · серийник · инвентарник · держатель on line 2. All D-05 columns kept, mobile-safe | D-05 discretion «порядок колонок списка»; Apple mail-style two-line list |
| D-05 column order on card/list line 2 | модель → тип → серийник → инвентарник → держатель → статус exactly as D-05 lists them | D-05 wording taken verbatim |
| List sort order | `created_at DESC` (newest first) | Not locked upstream; inventory operator adds a device and looks for it at the top; alphabetical matters at Phase 5 search, not pagination |
| Can edit change the device type? | No — type renders read-only in the edit dialog | REG-03 covers *fields*; the type defines the field set, switching would silently orphan typed columns; no requirement asks for type migration |
| Date format | `Intl.DateTimeFormat('ru-RU')` numeric → «05.02.2026» | CONTEXT discretion; compact, unambiguous, tabular in rows |
| Price format | `Intl.NumberFormat('ru-RU', { style: 'currency', currency: 'RUB', maximumFractionDigits: 0 })` → «124 000 ₽» | CONTEXT discretion; schema stores integer rubles |
| Peripheral serial hint text | «У периферии серийника может не быть — впишите инвентарный номер из 1С.» — shown under the serial field only when type = периферия | D-04 + explicit CONTEXT discretion area |
| Status display | Neutral pill (bg-black/5) for all four statuses; no color coding until phases 4–5 introduce status/warranty semantics | Phase 2 accent discipline; destructive reservation untouched |
| Nav order + redirect | «Устройства» before «Сотрудники»; `(app)/page.tsx` redirects to `/devices` | Devices are the app's core entity (roadmap: «сердце приложения»); one-line change, planner confirms |
| Mono for serial/inventory | `font-mono text-sm` in list line 2 and card values | Phase 2 explicitly reserved Geist Mono for «serial/inventory in phases 3+» |
