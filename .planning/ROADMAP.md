### 🚧 v1.3 «Удобство и выгрузка» (In Progress)

**Milestone Goal:** Сделать приложение ещё удобнее в ежедневной работе руководителя: выгрузка ведомости устройств в Excel для начальства и полноценный просмотр фото устройства с зумом.

**Покрытие (2/2):** EXP-02 → Phase 14 · PHOTO-01 → Phase 15

Зависимостей между фазами нет: Phase 14 — серверная поверхность (thin route, переиспользующий цепочку CSV-экспорта session→parse→strip→export, + pure `lib/device-xlsx.ts`; единственная новая зависимость `write-excel-file@4.1.1` exact pin, server-only), Phase 15 — клиентский остров без write-path риска. Порядок следует ценности и рискам research: XLSX первым — standalone-Docker спайк (первая задача фазы) гейтит бандлинг write-excel-file до построения фичи, питфоллы формата концентрируются в ней же. Центральная ловушка вехи — обратная ре-латигации: CSV-костыли (запятая-десятичная «21,5», ISO-строки дат, BOM, esc-гвард) остаются CSV-only — XLSX шарит модель колонок (метки из кейстоуна, WARRANTY_STATE_LABELS), но не рендереры ячеек. Лайтбокс — усиление существующего Base UI Dialog в `photo-grid.tsx`, НЕ замена на стороннюю библиотеку (иначе умирают delete-flow фото и ⌘K-проба `data-slot="dialog-content"`). Convenience-кандидаты research (сохранённые виды, печатный акт, QR-этикетки, quick actions, сводка, мобильная полировка) отклонены владельцем 2026-09-29 → v2 (VIEW-01..MOB-01 в REQUIREMENTS.md).

## Phase Details

### Phase 14: XLSX-выгрузка ведомости

**Goal**: Руководитель отдаёт начальству ведомость устройств файлом Excel, который открывается сразу и правильно — без настройки разделителей, без «числа как текст», без развалившихся номеров: те же 20 колонок и тот же состав строк, что CSV-ведомость (EXP-01), но с настоящими типами ячеек.
**Depends on**: Nothing (первая фаза вехи; строится на отгруженном CSV-контуре EXP-01 — та же цепочка route, парсер, стрип сентинелов, словари меток из кейстоуна)
**Requirements**: EXP-02
**Success Criteria** (what must be TRUE):

  1. «Скачать XLSX» доступен рядом с «Скачать CSV» на обеих существующих поверхностях экспорта — над списком устройств (filter-bar) и в ⌘K-палитре; состав строк паритетен CSV-ведомости: результат текущих фильтров, без фильтров = весь парк
  2. Файл открывается в реальном RU-Excel (дополнительно Numbers/Google Sheets) без диалога «восстановить книгу»: те же 20 колонок в том же порядке, жирная шапка, закреплённая первая строка, заданные ширины колонок
  3. Ячейки типизированы: дробная диагональ — настоящее число, которое Excel сам рендерит как «21,5» в RU-локали (сортировка и SUM работают); даты — настоящие Excel-даты; серийники и инвентарники — текст без научной записи («1,23457E+15» невозможен) и с сохранёнными ведущими нулями
  4. Parity с сайтом и гигиена файла: «Статус гарантии» берётся из общего словаря с цветом сайта (не параллельным); имя «устройства-ГГГГ-ММ-ДД.xlsx» корректно скачивается из Windows Chrome/Edge (RFC 5987); без сессии выгрузка данных не отдаёт (requireSession-first)
  5. Выгрузка работает на прод-способе деплоя: standalone-Docker спайк (первая задача фазы — `next build` + `node .next/standalone/server.js` + curl, до построения фичи) подтверждает, что write-excel-file корректно попадает в standalone-бандл

**Plans**: 3/3 plans executed

### Phase 15: Лайтбокс фото устройства

**Goal**: Руководитель рассматривает фото устройства крупно прямо в карточке — зум (клик/колесо/пинч), панорамирование и сброс — а существующий лайтбокс остаётся прежним по контракту: удаление фото и горячие клавиши карточки не ломаются.
**Depends on**: Nothing (независима от Phase 14 — клиентский остров без write-path риска; исполняется второй по нумерации вехи)
**Requirements**: PHOTO-01
**Success Criteria** (what must be TRUE):

  1. Клик по фото в карточке открывает лайтбокс крупно: существующий Base UI Dialog в `photo-grid.tsx` усиливается (панель шире ~max-w-5xl, зум-стейдж внутри DialogContent), а не заменяется; ESC закрывает, скролл-лок корректно снимается после закрытия
  2. Зум работает способами из требования: колесо мыши зумит к позиции курсора, клик (двойной) переключает зум/сброс, pinch на тачскрине зумит; drag панорамирует; масштаб ограничен диапазоном [1,4]
  3. Сброс работает предсказуемо: переключение на другое фото сбрасывает зум, агрессивный iOS pointercancel не залипает в зажатом состоянии
  4. Существующее поведение не сломано: удаление фото доступно из лайтбокса (кнопка остаётся смонтированной над трансформированным изображением), ⌘K-палитра открывается при открытом лайтбоксе (проба `data-slot="dialog-content"` жива), полная версия фото показывается без пустого мигания (loading-состояние)
