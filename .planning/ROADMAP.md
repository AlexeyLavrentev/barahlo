## Phase Details

### Phase 7: Live-поиск по сотрудникам

**Goal**: Оператор находит сотрудника в справочнике за секунды — живым поиском по имени и отделу, с тем же фолдингом (Ё/ё, гомоглифы), что и у устройств; попутно извлекается общий debounce-хук, который переиспользуют Фаза 11 и поиск устройств.
**Depends on**: Nothing (первая фаза вехи; строится на отгруженном v1.0)
**Requirements**: FIND-05
**Success Criteria** (what must be TRUE):

  1. При наборе в поисковой строке справочника список сотрудников фильтруется live (дебаунс, без перезагрузки страницы); быстрая печать и удаление не теряют символы (сценарии G-5-1/G-5-2 не воспроизводятся)
  2. Совпадение находится и по имени, и по отделу; «елкин» находит «Ёлкин» (Ё/ё-фолд), гомоглифы С↔C находят друг друга — на тех же правилах, что поиск устройств
  3. Запрос живёт в URL (?q=): «назад/вперёд», обновление страницы и шаринг ссылки сохраняют результат; новый запрос сбрасывает пагинацию на страницу 1; ссылки пагинации несут полный набор параметров; ?q= + ?page=999 корректно клампится
  4. Пустой результат показывает внятное «Ничего не найдено», а не пустую таблицу без объяснения; индикатор ожидания не блокирует набор текста
  5. Поиск по устройствам после рефакторинга на общий debounce-хук ведёт себя как раньше (Enter фиксирует сразу, «%» ищется буквально, локальные правки приоритетнее URL) — поведение сохранено

### Phase 8: CSV-ведомость полного контекста

**Goal**: Одна выгрузка отвечает на вопросы отчётности и аудита: у каждой единицы в файле видны владелец, отдел, конфигурация её типа, текстовый статус гарантии и стоимость.
**Depends on**: Nothing (полностью независима, наименьший diff вехи; может идти параллельно Phase 7)
**Requirements**: EXP-01
**Success Criteria** (what must be TRUE):

  1. К существующим колонкам выгрузки добавлены 4 типизированных конфиг-поля своего типа (диагональ / тип матрицы / порты / вид периферии) отдельными разреженными колонками — не одной текстовой «Конфигурацией» — и текстовый статус гарантии, совпадающий с цветом на сайте (parity через тот же warrantyPredicate)
  2. Выгрузка без фильтров содержит весь парк, с фильтрами — ровно отфильтрованный результат; число строк совпадает с реестром (общий deviceWhere, дрейф не представим)
  3. Файл корректно открывается в Excel (BOM, «;», ISO-даты); все новые ячейки проходят через общий esc-гвард — формула-инъекция через новые колонки невозможна
  4. Доступ только после авторизации: requireSession() — первое действие роута; запрос без сессии данных не отдаёт

### Phase 9: Клон устройства

**Goal**: Закупка N одинаковых единиц — один диалог: копии создаются из карточки оригинала с пустым серийником, редактируемой подсказкой инвентарника и чистой историей. Единственная миграция схемы вехи (serial → nullable) — решение фиксируется на уровне плана фазы.
**Depends on**: Nothing (независима; рекомендуется до Phase 10, чтобы churn `actions.ts` пришёл двумя обозримыми шагами)
**Requirements**: REG-06
**Success Criteria** (what must be TRUE):

  1. «Дублировать» на карточке открывает диалог с указанием количества (1..N); N копий создаются одной операцией, и сбой в середине пакета не оставляет «половину» копий (одна транзакция — всё или ничего)
  2. Копии отличаются от оригинала только идентификаторами: серийник пуст, фото, история перемещений и владелец никогда не копируются; копии «на складе», без привязки к сотруднику
  3. Инвентарный номер — редактируемая автоподсказка «следующий по шаблону оригинала» с сохранением нулевого паддинга; если шаблон не распознан, поле пустое и ничего не дописывается молча
  4. Поля одной закупки наследуются (тип, модель, дата закупки, стоимость, гарантия) — копия готова к выдаче сразу после подтверждения инвентарника

### Phase 10: Bulk-выдача и приём

**Goal**: Партия техники выдаётся одному сотруднику (или принимается на склад) одним диалогом вместо N походов по карточкам; оператор всегда точно знает, сколько единиц записано, а сколько заблокировано — и почему.
**Depends on**: Nothing жёсткого (порядок после Phase 9 рекомендован research: разделение churn `actions.ts`/`movement-schema.ts`)
**Requirements**: MOVE-06
**Success Criteria** (what must be TRUE):

  1. В списке устройств чекбоксы отмечают устройства в пределах страницы (в шапке — tri-state «выбрать страницу»); появляется плавающая панель «Выбрано: N» с «Выдать», «Принять» и «Снять выделение»
  2. Один диалог обрабатывает всю партию: один выбор сотрудника на все «Выдать»; «Принять» возвращает все отмеченные единицы на склад; итог — отчёт по каждой единице
  3. Семантика «всё или ничего» с предварительной валидацией статусов: если хотя бы одна единица не может сменить статус (например, уже выдана), ничего не записывается, и оператору видно, какая единица и почему заблокировала операцию
  4. Успех записывает по одному событию перемещения на каждую единицу (общее время/комментарий) — таймлайны согласованы; выделение сбрасывается только после подтверждённого успеха; повторный клик не создаёт дублей операций

### Phase 11: ⌘K глобальная палитра

**Goal**: Любая карточка — устройства или сотрудника — в паре нажатий из любого места приложения: ⌘K (работает и на русской раскладке), пара символов, Enter. Строится поверх стабильных поисковых бэкендов Фаз 7–8, без новых зависимостей.
**Depends on**: Phase 7 (жёстко: employeeSearchPredicate с Ё/ё-фолдом и debounce-хук); Phase 8 (мягко: пункт «Скачать ведомость»)
**Requirements**: FIND-06
**Success Criteria** (what must be TRUE):

  1. ⌘K / Ctrl+K открывает палитру с любой страницы, в том числе при активной русской раскладке (матч по event.code, не event.key); рядом с навигацией есть видимая кнопка с подсказкой «⌘K»
  2. Один запрос ищет по устройствам и сотрудникам одновременно с тем же фолдингом, что и списки — предикаты переиспользуются, а не переписываются («палитра находит то, что находит список»); результаты сгруппированы («Устройства», «Сотрудники»), лимитированы, с «Показать все» → переход в список с подставленным ?q=
  3. ↑↓ / Enter / Esc — полная клавиатурная навигация; выбор открывает карточку (по id) и закрывает палитру; архивные сотрудники находятся и несут бейдж «в архиве»
  4. Данные не протухают: палитра перезапрашивается при каждом открытии и по мере ввода, результаты не переживают закрытие; пока открыт другой диалог, ⌘K инертен; поисковая поверхность требует сессию
