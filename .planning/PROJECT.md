# Barahlo — учёт корпоративной техники

## What This Is

Веб-приложение для внутреннего учёта корпоративного оборудования (ноутбуки, мониторы, док-станции, периферия), заменяющее электронную таблицу. Пользователь — один руководитель, который закупает и раздаёт технику сотрудникам (50–200 человек); приложение мгновенно отвечает на вопросы вида «у кого ноутбук ещё с родной RAM», «где серийник ABC123», «у кого гарантия истекает» без обзвона и ползания по таблице.

## Core Value

Мгновенный точный ответ: где находится конкретная единица техники, кто ею пользуется и какая у неё конфигурация — за секунды, поиском или фильтром, а не полчаса расспросов.

## Requirements

### Validated

- ✓ Вход по логину+паролю, всё за авторизацией — Phase 1 (ACC-01/ACC-02)
- ✓ Данные в одном SQLite с автоматическими бэкапами и отрепетированным восстановлением — Phase 1 (ACC-03)

### Active

- [ ] Реестр устройств с типами (ноутбук, монитор, док-станция, периферия) и набором полей на тип
- [ ] Карточка устройства: модель, серийник, инвентарник, RAM, SSD + поля типа; фото, стоимость, закупка, гарантия, заметки
- [ ] Полная история перемещений: кто, когда, от кого/кому — таймлайн по устройству
- [ ] Карточка сотрудника: имя + отдел; список выданной техники
- [ ] Поиск по серийному и инвентарному номеру
- [ ] Фильтры: «ноуты без апгрейда RAM», «гарантия истекает» и т.п.
- [ ] Дашборд: сколько единиц, у кого что, что на ремонте/списано
- [ ] Подсветка истекающей гарантии
- [ ] Красивый современный UI в духе Apple (apple-design гайды)

### Out of Scope

- Импорт из существующей таблицы — пользователь начинает с нуля, старую бросает
- Роли и права (несколько пользователей с разными правами) — пользуется один человек
- Самообслуживание сотрудников (вход сотрудников, заявки) — только руководитель
- Слежение за статусом закупки («заказано, в пути») — фиксируется факт покупки, не процесс
- Учёт ПО/лицензий/доступов — реестр про железо

## Context

- Сейчас учёт в электронной таблице — неудобно: чтобы узнать конфигурацию ноутбука сотрудника, нужно обзванивать/переспрашивать
- Типовой сценарий-боль: перед закупкой комплектов расширенной памяти узнать, у кого ноутбук НЕ делал апгрейд RAM — сейчас это полчаса вопросов
- Масштаб: 50–200 сотрудников, сотни единиц техники — нужна пагинация и вменяемая производительность списков
- Деплой: сервер внутри сети компании; доступ из офиса
- Интерфейс на русском (пользователь и данные русскоязычные)
- Дизайн: современный, минималистичный, в духе Apple — использовать гайды skill `apple-design`

## Constraints

- **Деплой**: внутренний сервер компании — без внешних облаков, доступ из офисной сети
- **Пользователи**: ровно один аккаунт (логин+пароль) — без ролевой модели
- **Данные**: старт с нуля, без миграции из Excel/Google Sheets
- **Дизайн**: Apple-эстетика (чистота, типографика, воздух) — не «админка из 2010»
- **Производительность**: списки и фильтры должны летать на сотнях устройств

## Key Decisions

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| Один пользователь с логином+паролем | Внутренняя сеть + единственный оператор; полноценный вход от чужих глаз | — Pending |
| Фиксированные поля устройства, а не конструктор атрибутов | RAM/SSD/серийник покрывают реальные сценарии; конструктор = лишняя сложность | — Pending |
